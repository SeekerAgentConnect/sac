Capabilities

This is a switch, not a revocation. Turning a capability off makes every credential of that kind refused from the next call; turning it back on makes the same ones work again. Revoking a credential below ends it for good.

Disabling the relay stops new wake-ups at once. Authorizations phones already gave are kept, so enabling it again does not ask anyone to pair or authorize anything twice — and a wake-up already handed to Firebase cannot be recalled.

Credentials

A credential is shown once, when it is created, and only its hash is stored. There is no way to read an existing one back — rotate instead. A publishing credential and a relay credential look identical and are not interchangeable: presenting one where the other belongs is refused, so the kind is listed beside every ID.

Add a credential (rotation)

The new credential works immediately and the existing ones keep working, so the server can switch without downtime. Revoke the old one once it has.

A credential only works for the capability it was issued for, and only while that capability is enabled above.

Revoke every credential

This server stops being able to publish and to relay from the next request, of both kinds at once. Its manifest and the feed items it already published stay on the feed, and the authorizations phones gave it are kept — revocation ends what it can present, it does not withdraw what was published or what anyone agreed to.

Forget server

This removes the registration, its credentials, its manifest, every feed item this gateway holds for it and every push authorization phones gave it. It is not a rotation and it is not a revocation: the public feed for this channel stops existing, and phones paired with this server directly stay paired and simply stop being woken through this gateway.

Phones that already read its feed items keep their own copies until their owners remove the feed. This clears what the gateway holds, not what a device decided.
