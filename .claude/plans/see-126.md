# SEE-126 — CopyTrading demo trader web UI

## Goal

Password-gated HTML UI for hackathon judges to create/list/cancel/retry sandbox swap
signals through the **existing** CopyTrading `/v1` API. Docker service beside the
demo in `deploy/server`. API token never reaches the browser. `/v1` stays off the
public origin.

## Shape

- `publisher/cmd/copytrading-admin` + `publisher/internal/admin` — same image,
  different entrypoint (`/copytrading-admin`), same pattern as `copytrading-ctl`.
- `cmd/copytrading` unchanged except an optional global create cap
  (`PUBLISHER_CREATE_LIMIT`, default 0 = unlimited).
- UI is an HTTP client of `/v1/status`, `/v1/manifest`, `/v1/requests`
  (create, list, show, cancel, retry). No second write path.
- `compose.demos.yaml` service `copytrading-admin`:
  `network_mode: service:copytrading`, calls `http://127.0.0.1:8092`, holds
  `PUBLISHER_API_TOKEN` from `secrets/copytrading/`.
- CopyTrading API remains `127.0.0.1:8092` (host publish is still the proxy on 8093).
- UI listens `0.0.0.0:8096` inside that namespace (not published to the host).
- Gateway Caddy (`Caddyfile` and `Caddyfile.tailscale`) reverse-proxies `/trader*`
  to `copytrading:8096` on the existing origin. No fourth Funnel port, not `:10000`.
- Cookie `Path=/trader`. Do not use `compose.public.yaml`.

## Auth and limits

- Named bcrypt file `secrets/copytrading/admin-passwords` (`name:$2a$…`).
- `copytrading-admin hash <name>` writes that line to stdout.
- Session secret file; cookie HttpOnly, Secure, SameSite=Strict, path-scoped.
- Reload passwords on mtime; missing name invalidates the session immediately.
- Failed logins: one message; bcrypt a dummy hash for unknown names.
- In-memory limits: login failures per IP and per name; creates per judge;
  cancel/retry higher. Publisher create cap on the demo service.
