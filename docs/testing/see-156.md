## The phone

The Android work is written and committed and **is not verified**. `pnpm check:android` needs a JDK
and the Android SDK; this host has neither, and `dl.google.com` answers 404 for every path from here,
so the command-line tools cannot be fetched and no container can be built that has them. A JDK was
obtained and discarded as useless on its own. Nothing was compiled.

What exists, unrun, is:

| File | What it would prove |
| --- | --- |
| `access/AccessProofTest.kt` | the challenge, status and redeem texts are byte for byte the fixture the publisher pins (`fixtures/restricted-feeds/challenge.json`), and the wallet signature in that fixture verifies over exactly those bytes |
| `access/FeedAccessManagerTest.kt` | a forged challenge never reaches the wallet, a wallet that signs something else is not a signature, the gateway's refusal is what records a revocation, another wallet does not inherit access, removing a feed takes its key with it |
| `access/storage/FeedAccessStoreTest.kt` | the record holds a decision and no secret, and a document this build cannot read is absent rather than guessed at |
| `servers/RestrictedFeedAccessTest.kt` | a policy this build does not know is refused rather than read as public, a feed that was restricted is never served as public, and a reference can say restricted but can never name the origin a wallet is proved to |
| `StageBoundaryTest.kt` (changed) | `access/storage` is an authorized storage package and `access/DeviceKeys.kt` is the one carve-out from the no-keys rule, still a signing-only Keystore key |

The Go half of the shared-fixture check (`TestTheChallengeIsTheSharedFixtureByteForByte`) **did**
run and pass, so the fixture is known to match the publisher. What is unproven is that the Kotlin
builds the same bytes. Treat the first `pnpm check:android` on a machine with the SDK as the real
first run of all five files.

## What could not be run

| Blocked | Why |
| --- | --- |
| `pnpm check:android`, and therefore every Android unit test, lint, Roborazzi capture and APK | no JDK and no Android SDK on this host; `dl.google.com/android/repository/…` returns 404 for every path, including `repository2-1.xml`, so the SDK cannot be installed and Google's Maven cannot be reached |
| A physical device run | ticket constraint |
| The end-to-end demo with approved and denied devices, active-stream revocation and missed-push recovery | needs a phone with a wallet, a broker and a deployed gateway registered as restricted. Nothing in the repository records that the deployed signals gateway has been switched to `restricted` yet; until an operator runs `feed-gatewayctl access`, the publisher will refuse to publish, by design |
| The Postgres store's own migration | its tests need a live Postgres (`BROADCAST_TEST_DATABASE_URL`) and skip without one. The SQLite v7 migration **is** covered, by `TestTheAccessColumnsAreAddedWithoutLosingAnythingOrChangingWhoMayRead` |
