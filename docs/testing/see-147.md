# SEE-147 verification record

Date: 2026-09-23

SEE-147 adds the foreground in-app notification banner for a new request, a new signal, and a
paired server that ends the pairing. It changes nothing about who can approve, sign, or send, and
nothing about background delivery.

## Seeding the baseline

Review found that the first foreground snapshot was gated on `ConnectionsUiState.loaded` alone,
which is true as soon as `ConnectionRepository.load()` has read the stored connections. Those
records carry no pending requests and no proposals: the inbox is filled by the fetch the app makes
when it opens, and the proposals by `ProposalRepository.load()`. The baseline was therefore taken
against an empty waiting set, and both of those reads then looked like arrivals — a cold start
replayed an inbox the owner had been carrying for days as a burst of banners.

Three signals now stand behind readiness, and `SeekerVaultApp` passes
`state.fetched && (operations == null || operationsState.loaded)`:

| Signal | Means | How it got right |
| --- | --- | --- |
| `ConnectionsUiState.loaded` | the stored connections have been read | unchanged |
| `ConnectionsUiState.fetched` | the opening fetch has settled for every usable connection | new; `refreshAll()` returns its jobs and the startup coroutine joins them |
| `OperationsUiState.loaded` | the stored proposals have been read | was hard-coded `true` on the first combine emission; now `ProposalRepository.loaded`, set at the end of `load()` |

`fetched` implies `loaded`, and a build without operations holds no proposals, so there is nothing
there to wait for. Tightening `OperationsUiState.loaded` also makes the two places that already
used it — closing a review whose proposal is gone — correct at startup rather than merely correct
later.

Each of the two view-model tests was confirmed to fail against the unfixed code: with
`OperationsUiState.loaded` back to `true` and `fetched` set beside `loaded`, both fail and the rest
of the suite passes.

## One bug found and fixed on the way

The banner's drag read its pointer from inside the layer it was translating, so each move's reported
travel was cancelled by the previous move's translation and the drag tracked the finger at half
speed: a 72dp swipe needed 144dp of finger. The threshold tests found it at three different step
counts, and the gesture now sits outside the moving layer. It was never reachable outside SEE-147's
own banner.
