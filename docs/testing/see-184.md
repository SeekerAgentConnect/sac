# SEE-184 verification record

Date: 2026-10-10

SEE-184 adds runtime Solana RPC settings per network and routes every on-device chain read — account
verification before signing and confirmation tracking afterwards — through one network-aware
resolver ([solana-rpc.md](../wiki/solana-rpc.md)). This records what was verified, how, and what
was not. No real funds were used anywhere.

## Coverage

| Acceptance criterion | Evidence |
| --- | --- |
| A mainnet and a devnet connection work concurrently, each through its own network's RPC | `SolanaRpcTest.aMainnetAndADevnetOperationRunTogetherEachThroughItsOwnEndpoint`: two local JSON-RPC servers identified only by genesis hash; a mainnet account read, a devnet account read and a devnet status read in flight together; each server saw only its own network's reads. |
| Only a mainnet RPC, general empty: Prediction verification works and the swap fee uses the same resolver | `SolanaRpcTest.withOnlyAMainnetEndpointPredictionTablesResolveAndTheSwapFeeIsVerifiedThroughTheSameOne`: the real `JupiterExecutionProvider` prepares an order whose lookup tables are served over HTTP by the mainnet endpoint, then `decideSwapFee` charges after reading the fee account through `rpc.on(MAINNET)`; one genesis proof for both; devnet has no endpoint and nothing is sent anywhere. |
| Editing devnet affects devnet only; persists across restarts; foreground and background | `SolanaRpcTest.anEndpointReplacedAtRuntimeIsUsedForTheNextReadAndTheOldProofIsDropped` (only `DEVNET` is reported changed; mainnet untouched), `theOwnersSettingsOutliveTheProcessAndResetRestoresTheBuildDefault` (a new resolver over the same files), `RpcSettingsActivityTest` (mainnet unchanged after saving devnet). Background work uses the process's one resolver (`SeekerVaultApplication.rpc`), which reads the stored settings at start, so `ConfirmationWorker` in a fresh process sees them. |
| Wrong-cluster endpoints refused for account reads and confirmation tracking | `SolanaRpcTest.anEndpointServingAnotherClusterIsRefusedForAccountReadsAndForConfirmations` (`rpc_wrong_cluster` for both; only `getGenesisHash` reached the wrong endpoint; it cannot be saved either), `aGeneralOnlyBuildServesTheClusterItProvesAndNoOther`, `ConfirmationTrackerTest.theClusterIsTheOneTheRecordWasBoundToAndAnEndpointForAnotherIsRefused`. |
| Pending/history transactions keep their network and resume after their endpoint is repaired | `ConfirmationTrackerTest.aRecordKeepsItsClusterThroughEveryChangeAndResumesWhenItsOwnEndpointIsRepaired`: a devnet record stuck on a wrong-cluster devnet setting; changing mainnet's endpoint leaves it waiting; repairing devnet's makes it due at once and it settles on devnet; mainnet is never asked; the record stays devnet's throughout. |
| Reset restores the build default; legacy general-only works for its verified cluster | `SolanaRpcTest.theOwnersSettingsOutliveTheProcessAndResetRestoresTheBuildDefault`, `theOwnersSettingComesFirstThenTheNetworksOwnThenTheGeneralOneWithNoFailover`, `aGeneralOnlyBuildServesTheClusterItProvesAndNoOther`, `RpcSettingsActivityTest`. |
| Debug-only local validator exception preserved | `SolanaRpcTest.aLocalValidatorIsAcceptedOnlyWhereADebugBuildExplicitlyConfiguredOne` (explicit devnet in debug: yes; mainnet: no; general: no; release: no). |
| Release gate does not need a redundant general RPC; general-only builds still pass | `scripts/release-android.test.mjs` (mainnet alone satisfies `solanaRpc`; general alone still does; devnet alone does not), `scripts/check-swap-fee-build.sh` (a fee build with only `solanaRpc.mainnet`; refused with only devnet). |
| No server can supply the endpoint; no full URL in logs or history | `StageBoundaryTest.everyChainReadGoesThroughTheOneResolver` (readers, the resolver and the settings store are built only in the composition root), `theChainReaderReadsAndIsTheApplicationsOwn`, `storageKeysAndBackgroundWorkStayInsideTheirNarrowPackages`; `ConfirmationTrackerTest` asserts a key in the URL path never reaches History. |

### Deliberate breaks

Each was applied alone, run under a time limit, and the source restored and compared with `cmp`:

| Break | Caught by |
| --- | --- |
| Account reads skip the genesis proof | 4 `SolanaRpcTest` cases |
| A setting change keeps cached genesis proofs | `anEndpointReplacedAtRuntimeIsUsedForTheNextReadAndTheOldProofIsDropped` |
| `endpointChanged` re-arms every network, not just the changed one | `aRecordKeepsItsClusterThroughEveryChangeAndResumesWhenItsOwnEndpointIsRepaired` |

## Manual Android verification of the settings flow

**NOT RUN** on this host: it has no KVM access, so no emulator could be started
([emulator-e2e.md](../development/emulator-e2e.md)). The same flow runs automatically in
`RpcSettingsActivityTest` against the real activity. To run it by hand on an emulator or a device —
no transaction is needed, and nothing spends funds:

1. Build a debug APK with only a devnet default:
   `apps/android/gradlew -p apps/android :app:assembleDebug -Pseekervault.solanaRpc.devnet=https://api.devnet.solana.com`
   and install it.
2. Open **Wallet → Solana RPC**. Expect three cards. Devnet: `api.devnet.solana.com · this build's
   endpoint`, then **Serves Solana devnet.** Mainnet and testnet: **No endpoint set** and a line
   saying their transactions can't be prepared or followed. **Use build default** is disabled.
3. In devnet's field enter `https://api.mainnet-beta.solana.com` and tap **Check and save**. Expect
   **Not saved. It serves Solana mainnet, not devnet…**; the card still says the build's endpoint.
4. Enter `http://example.com` (release build) or `https://user:pw@example.com` — expect the URL
   refusal. Enter an unreachable `https://10.255.255.1` — expect **Not saved. It couldn't be
   reached.**
5. Enter another devnet endpoint you have, tap **Check and save**: the card shows
   `<host> · your setting` and **Serves Solana devnet.** Mainnet's card is unchanged.
6. Force-stop the app and reopen the sheet: the devnet setting is still there.
7. Tap **Use build default**: the card returns to the build's endpoint and is checked again.
8. Optional, with a devnet direct server ([chain-confirmation.md](../wiki/chain-confirmation.md)).
   The sheet refuses a mainnet URL for devnet, so to see a repair, build with
   `-Pseekervault.solanaRpc.devnet=https://api.mainnet-beta.solana.com`, send a devnet transfer,
   and see History say the endpoint serves another cluster. Then save a real devnet endpoint in
   the sheet and watch the record settle without restarting the app.
