# SEE-141 verification record

Date: 2026-09-21
Tested commit: `ed16d79` plus the SEE-141 working tree (branch `superset/feat/see-141`).
Toolchain: Go 1.27.1 darwin/arm64, Node.js 24.21.0, pnpm 12.3.4, Caddy 2.10.2, Docker Compose v2
(configuration resolution only — no daemon is reachable from these sessions).

SEE-141 adds a password-protected admin page to the existing feed gateway, in the same image and
the same process, so the operator can register publishers, rotate and revoke credentials and remove
a publisher from a browser instead of a shell on the host that holds the database. The CLI is
unchanged in purpose and remains the recovery path.

## What was built

| Ticket item | Where it is |
| --- | --- |
| Admin UI inside `feed-gateway/`, in its existing image and process | [`internal/admin`](../../feed-gateway/internal/admin), composed by `gateway.Build` and served on a third listener by `Gateway.Run` |
| A configurable `/admin` route, or an equally explicit boundary | Both: `BROADCAST_ADMIN_PATH` (default `/admin`) on `BROADCAST_ADMIN_ADDRESS` (default `127.0.0.1:8092`), a third socket that must differ from the read and publisher ones |
| The existing storage boundary and authoritative store; shared logic with `feed-gatewayctl` | `storage.PublisherAdminStore` for both surfaces; [`internal/credential`](../../feed-gateway/internal/credential) is the one place a credential is minted, hashed and named. Nothing shells out to the CLI |
| Operator login with a configured hash and bounded sessions | PBKDF2-HMAC-SHA256 (`crypto/pbkdf2`, 600 000 iterations, per-hash salt, constant-time compare); server-side sessions, `HttpOnly`/`SameSite=Strict`, `Secure` when the public origin is HTTPS, absolute expiry, real logout, per-session CSRF plus `Sec-Fetch-Site`, and login rate limiting under the deployment's trusted-proxy policy |
| Admin surface disabled when credentials are absent | No hash ⇒ no handler, no listener, no route. Not a disabled route and not a setup endpoint |
| List and inspect publishers | Label, server ID, channel, creation time, host metadata, published display name, credential IDs and timestamps with `Publishing enabled` / `No active credentials`, and manifest/publication evidence with `No publications yet`. No subscriber is counted and no publisher is called "connected" |
| Register without restarting the gateway | One transaction: the publisher, its host and its first credential, or nothing. Duplicate identities are refused on both surfaces. The raw credential is shown once with a copy control, beside the server ID, public origin, publisher API URL and channel |
| Additive rotation, single and total revocation, destructive removal | The CLI's semantics, unchanged; `forget` is a separate action behind typing the publisher's own ID back |
| Minimal administrative events | `admin action` log lines with action, target and outcome. No password, session, publishing secret or request body |
| Bundled assets, no CDN, security headers | One stylesheet and one script embedded in the binary; `Content-Security-Policy: default-src 'none'`, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` |
| Deployment/ingress changes only as needed | `deploy/feed/compose.yaml` (the variable group and a loopback-published port), `deploy/ingress/feed/Caddyfile` (one `/admin` block the operator may delete), `deploy/seeker-gateway.yaml` (internal port, edge route, and the hash declared **empty** — no credential is committed), `feed-gateway/Dockerfile` (`EXPOSE`, and deliberately no default admin address) |

Storage moved from schema v3 to v4: `publisher.host`, one `ALTER TABLE ADD COLUMN` with an empty
default. The live table list is unchanged, so `TestTheStoreKeepsOnlyPublicFeedState` still pins the
same six public tables.

**Two things found in self-review.** A revocation submitted by hand could name another publisher's
credential from this publisher's page — the operator is entitled to revoke it from the right page,
but the recorded event would have named the wrong publisher, so the ID is now checked against this
publisher's own credentials first (`TestARevocationOnlyEndsThisPublishersCredential`). And
`internal/gateway/secrets.go` — a UUID minter, a token minter and a token-shape check left
unreferenced by SEE-130's retirement — was removed rather than left beside the new
`internal/credential`, since the ticket asks for one credential algorithm rather than two spellings
of one.

**A change found by verification.** The password hash was first encoded PHC-style with `$`
separators. `docker compose config` showed the value arriving as `pbkdf2-sha256$$600000` — Compose
interpolates `$name` inside an env file, so a pasted hash reached the container truncated at its
first separator, with a login that simply never succeeds as the only symptom. The separator is now
a dot, which is outside base64url's alphabet and survives env files, YAML and consoles unescaped.

## What this does not claim

The admin page does not make the demo's storage durable. On the current App Platform deployment the
SQLite file can be discarded when a container is replaced, taking registrations and credential
hashes with it; the page is what makes recovering from that a login and a few forms rather than a
console session. Lost publisher secrets cannot be recovered from hashes, and nothing here preserves
or restores data automatically.
