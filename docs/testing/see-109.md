## Focused acceptance coverage

- A preview and cancellation write no binding and do not consume an invitation. Authenticated
  revocation is idempotent; expiry, revocation, replay, concurrent redemption and a used token are
  rejected.
- Two fresh invitations for the same server-scoped user create two distinct connection IDs. A
  request must name the exact connection; retrying a request ID against another binding conflicts,
  and revoking either device leaves its sibling active.
- Server, user and device substitutions are rejected, and another authenticated server cannot read
  the invitation, binding, request or result.
- Invalid and tampered references, cold and warm intent delivery, and duplicate warm imports are
  covered on Android. Preview and duplicate import do not redeem.
- Manifest mode, gateway origin, environment and required plugin contract are validated before SAC
  stores a connection. The manifest's sandbox/production promise survives storage and reload.
- The publisher SDK retries a temporary offline completion poll and then observes the same
  invitation become connected. Private results retry from SAC's durable local record without
  opening the wallet again.
- Trading, prediction and MCP-backed profiles use the same SDK invitation/request path in both the
  no-website command and developer-owned webpage examples.
