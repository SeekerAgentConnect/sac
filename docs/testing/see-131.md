# SEE-131 — Direct Server SDK extraction

Date: 2026-09-20

Branch: `superset/feat/see-128`

PR: [#38](https://github.com/BrRenat/SeekerAgentWallet/pull/38)

This is step 3 of 8 under SEE-128. It extracts the reusable TypeScript direct-server engine and
prepares a private npm artifact. It does not publish that artifact, relocate/package the MCP host,
change feed infrastructure, or install/run Android on a real device.

## Delivered boundary

- `server-sdk/` owns the unchanged direct SQLite schema/migrations, server identity, pairing and
  phone credential rules, request lifecycle/idempotency/result validation, manifest, phone Connect
  services, update convergence, live bridge and optional content-free invalidation scheduler.
- The public ESM package exports only `@seeker-vault/server-sdk` and
  `@seeker-vault/server-sdk/protocol`. Initialization, database/public origin, limits, logger,
  listener and optional provider/invalidation adapters are explicit. Import alone has no resource
  or process side effect.
- At the SEE-131 handoff, the then-current product/MCP host was ready for SEE-132. It imported only
  the two public SDK entry points; SEE-132 subsequently moved that host intact to `mcp-server/`.
- The package is private `0.1.0`, ESM, Node `>=24.21.0 <25`, with exact runtime dependencies and a
  `dist`/README/LICENSE file allowlist. No npm credential, `npm publish`, upload or auto-publish
  workflow exists.

There is no database migration in SEE-131. Opening the same database preserves server ID, paired
phone and credential hash, wallet binding, requests, idempotency keys, prepared versions, results,
manifest revision and update history. Rollback is the existing verified database backup/restore
procedure; an older binary must not open a schema it reports as newer.
