# SEE-146 verification record and lifecycle guide

Date: 2026-09-24

Two things live here: what was established about the SKR staking program before any code was written,
and the owner-run test that is the only way to prove a real staking action end to end. The automated
checks are offline and prove what they can; they do not prove on-chain execution, and nothing here
claims otherwise.

## What was established on chain

Verified against mainnet-beta on 2026-09-24, and against the program's own on-chain Anchor IDL
(`4aAEUKCcju9iAEAgdeaNz4RC7sCPv63q5g714nw4QY68`, whose decompressed JSON is byte-equal to the
`solana-mobile/react-native-samples` copy).

| Fact | How it was established |
| --- | --- |
| The program is `SKRskrmtL83pcL4YqLWt6iPefDqwXQWHSw9S9vz94BZ`, on **mainnet-beta only** | All five addresses return "not found" on devnet. The ticket's warning not to assume an official devnet is correct, so this server declares mainnet and nothing else. |
| `stake_config`, `stake_vault`, `guardian_pool` and `user_stake` are program-derived | Each derivation reproduces the live address exactly; `user_stake` was checked against a real staker's account (`12BbTo3vUzvVzYMEtdkoMaSj9BHda4KsBP6VtbRH1rq2`). |
| Only the program ID and the SKR mint are roots of trust | Everything else follows from them, on the server and on the phone independently. |
| `unstake` takes **shares (u128)**, not SKR | The IDL's argument, confirmed by a real `stake`/`unstake` pair. |
| `withdraw` and `cancel_unstake` take no argument at all | Zero-length instruction data in the IDL and on chain. |
| `withdraw` requires no signature from the owner — it is a crank | The IDL declares `user` writable and not a signer; the owner's signature on it is the fee payer's. |
| The cooldown is `StakeConfig.cooldown_seconds`, 172800 (48 h) at capture | Read from the account, and read again on every preparation and every review. |
| A `tokens → shares → tokens` round trip loses up to one base unit | The program floors. Full-position unstaking therefore passes `UserStake.shares` exactly rather than reconverting. |
| "Unstaking again combines the amounts and resets the cooldown" is **only true while the cooldown is still running** | Once it has finished the program answers `WithdrawRequired` (6017). The server refuses first, by name; the phone refuses independently. |
| `solana-mobile/react-native-samples` carries **no licence file** | So none of its source is copied. Discriminators, layouts and seeds are derived, and each derivation is asserted against the IDL and against live accounts. |

The accounts themselves are checked in at
[`skr-staking-server/src/testing/accounts.ts`](../../servers/mcp-skr-staking/src/testing/accounts.ts),
copied byte for byte off mainnet on the same date: the singleton config, the official guardian's
pool, the vault, and a real staker who holds shares *and* has a pending unstake — the state most
worth testing and the one a made-up fixture would miss. Two independent records of the vault balance
agree, and the `stake` instruction is rebuilt account for account and byte for byte from a real
mainnet transaction.

## The owner-run lifecycle test

There is no official devnet deployment, so the only way to prove a real staking action is to do one
with a small amount of real SKR on mainnet. Everything below is the owner's to run.

**Before you start.** A phone with Seeker Agent Connect and a wallet holding a little SKR and enough
SOL for four transaction fees. A staking server running and reachable. Plan for the **48-hour wait**
in step 4: the cooldown is real and cannot be skipped.

1. **Pair and connect.** Run `skr-staking-server/src/cli.ts pair`, add the connection on the phone,
   and connect the wallet. Check `get_staking_status`: it should report the wallet's SKR, zero staked
   and zero pending, with `cooldown_seconds` read from the chain.

2. **Stake a small amount.** Ask the agent for `request_stake` with just over `minimum_stake_skr`.
   On the phone, check that the review says *Stake*, shows that amount in SKR, names your wallet and
   your derived stake account, says Mainnet, and that the verdict is verified. Approve, sign in the
   wallet, and wait for the result. Then `get_staking_status`: `staked_skr` should be what you staked
   (give or take the flooring of a single base unit), `available_skr` lower by the same.

3. **Start unstaking part of it.** `request_unstake` for half. The review must say **Start unstaking**
   and that nothing moves yet — not *withdraw* — must show what will be left staked, and must show
   when it becomes withdrawable. Approve. Then `get_staking_status`: `unstaking_skr` is the amount,
   `withdrawable` is false, and `withdrawable_at` is about 48 hours away.

4. **Try to withdraw early, and expect a refusal.** `request_withdraw` now. The server should refuse
   before creating anything, saying the cooldown has not finished. If a request does reach the phone,
   the review must refuse it too — that is the independent check doing its job.

   Also worth doing here: `request_unstake` again for a little more. It should be allowed, and the
   review must warn in red that approving restarts the cooldown. Either approve it (and expect
   `withdrawable_at` to move) or reject it; both are a valid result for this step.

5. **Cancel, and check it went back to work.** `request_cancel_unstake`. The review must say the
   pending amount goes back to staking and must show no amount you chose — the program cancels all of
   it. Approve. Then `get_staking_status`: `unstaking_skr` is zero and `staked_skr` is back up.

6. **Unstake again and wait out the cooldown.** `request_unstake` for the amount you want back, then
   wait past `withdrawable_at`. Waiting is the test.

7. **Withdraw.** `request_withdraw`. The review must say **Withdraw**, show the amount the program
   recorded, and — if your wallet has no SKR account any more — say that one is being created.
   Approve. Then `get_staking_status`: `unstaking_skr` is zero and `available_skr` is back up by the
   withdrawn amount.

8. **Close the position.** `request_unstake` with an amount at or above `staked_skr`, wait the
   cooldown, and `request_withdraw`. Afterwards `staked_skr` and `shares` must both be exactly zero:
   a whole-position unstake that left dust behind would be the flooring bug this ticket exists to
   avoid.

**Record, for each step:** what the review said, the transaction signature, and what
`get_staking_status` said afterwards. A step where the phone's review disagreed with the server is
the finding worth reporting — that disagreement is what the phone is for.

**What this does not prove.** Nothing in this guide exercises a hostile server. The cases where a
server builds something other than what it asked for are covered in `StakingInspectionTest`, and no
real server would produce one on request.
