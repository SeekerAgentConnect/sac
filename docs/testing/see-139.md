# SEE-139 verification record

Date: 2026-09-20

SEE-139 fixes the five related Home/feed/prediction presentation regressions without changing who
can approve, sign, or send anything.

## Coverage

| Ticket item | Implementation and regression evidence |
| --- | --- |
| Feed shown disconnected on Home | `ConnectionsViewModel` carries `ForegroundFeedsState`; Home resolves a feed by gateway origin and never interprets its deliberately absent credential as disconnection. Mapper and ViewModel tests cover Live and Reconnecting transitions. |
| Prominent red shared-feed notice | Connection details use the same feed listener state and problem classification. The old explanatory status string is removed; a Compose test asserts Live status and absence of the notice. |
| Prediction copy | Prediction discovery writes the provider's event question into the common request title, with market title as the missing-event fallback. Publisher tests cover exact request copy, fingerprint/idempotency participation, SQLite update/restart retention, and discovery revision changes. Android uses that title and replaces the prediction footer's `Nothing moves` fallback with the humanized `provider` term. |
| Feed pending count | Home counts only the feed's current `PendingItem.Signal`s, which are already derived from `ProposalStanding.Open`, and renders the same `N pending` wording as direct servers. The mapper test covers count changes alongside feed liveness. |
| Stable carousel insert | Stable item keys, rather than mutable indices, own the active treatment. Compose state tracks newly inserted IDs before the visible anchor, overlays an accurate `N new` marker, and removes IDs as they enter the visible set. The focused Compose test proves the current card keeps its bounds, two insertions are counted, and the marker clears after viewing. |

The change adds publisher SQLite schema version 3 with a monotonic migration from existing versions.
It does not change protocol schemas, generated code, security authority, or RFC scope.
