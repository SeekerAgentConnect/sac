# SEE-185 verification record

Date: 2026-10-11

SEE-185 moves the Solana RPC endpoints and the SAC swap fee into the trusted gateway's client
configuration ([client-config.md](../wiki/client-config.md)), makes every feed signal name its
network, chooses a feed operation's wallet per operation and network, and replaces server-declared
environments with a per-operation preview on the phone ([environments.md](../wiki/environments.md)).
This records what is covered automatically, what checks run, and the manual Android procedure. No
real funds were used.

## Manual Android UI verification

**NOT RUN** on this host: it has no KVM access, so no emulator could be started and no device is
attached ([emulator-e2e.md](../development/emulator-e2e.md)). To run it on an emulator or a Seeker:

1. **Configure the gateway.** On a gateway you operate (local, or the deployment in
   [emulator-e2e.md](../development/emulator-e2e.md)):

   ```sh
   feed-gatewayctl client-config set-rpc --network mainnet --url https://api.mainnet-beta.solana.com
   feed-gatewayctl client-config set-rpc --network devnet --url https://api.devnet.solana.com
   feed-gatewayctl client-config set-fee --bps 0
   feed-gatewayctl client-config show
   ```

   Expect `show` to print both endpoints and no fee, with revision 1 or higher. Run the same
   `set-rpc` again: it prints `unchanged` and the revision stays where it was. Try
   `--url https://user:pw@rpc.example.com`: refused, nothing saved. The admin page's **Client
   configuration** shows the same values.

2. **Build against it** and install:

   ```sh
   apps/android/gradlew -p apps/android :app:assembleDebug -Pseekervault.gatewayUrl=<gateway origin>
   # or: SEEKER_GATEWAY_URL=<gateway origin> scripts/emulator.sh build
   ```

   The Wallet tab has no **Solana RPC** entry.

3. **Add a public feed with no wallet.** Add the CopyTrading demo feed from Discover or its
   `seekervault://feed` link. The app asks for no wallet. The detail sheet shows no **Access
   wallet** row. Paste a feed link that names another gateway: expect "This feed is on another
   gateway…", and nothing added.

4. **Publish signals on two networks.** Publish a mainnet swap signal from the CopyTrading demo with
   `publishctl create --network mainnet …` ([copytrading-template.md](../wiki/copytrading-template.md)).
   The demo declares only mainnet, so for a devnet signal register a second publisher on the gateway,
   publish a manifest for it that declares mainnet and devnet, and publish a contract-2 request with
   `action.network` set to devnet through the gateway's Connect JSON API
   ([services/gateway/README.md](../../services/gateway/README.md)). Add that feed too.
   Jupiter serves only mainnet, so the devnet signal can't be prepared; it is there to show the
   network and wallet. Optionally, publish a document through `PublishProposal`: it names no network,
   and its review says "This signal doesn't say which Solana network it is for, so nothing can be
   executed from it".

5. **Per-network wallet choice.** Have one authorized mainnet wallet profile and two authorized devnet
   ones. Open the mainnet signal: **Network** reads "Mainnet · from this signal" and **Wallet** is the
   only mainnet profile, chosen without asking. Open the devnet signal: with two devnet profiles,
   expect "No wallet on Devnet is chosen for this feed…" and **Choose wallet**. The **Wallet for
   Devnet** sheet stacks over the review, lists every profile, and lets you choose only the
   authorized devnet ones. Choose one, close the review and open it again: the choice is remembered.
   The mainnet signal still uses the mainnet profile. With two authorized mainnet profiles A and B,
   open a mainnet **prediction** signal, choose A, choose a side and stake and get a quote; then tap
   **Choose wallet** under the wallet row, choose B: the quote is dropped, Approve is unavailable,
   and the next quote is for B (covered in unit tests by `PredictionWalletChoiceTest`).

6. **Preview, then execute.** On the mainnet signal, prepare. Tap **Preview without sending**. The
   wallet does not open. Expect "Previewed. Nothing was signed and nothing was sent, and this signal
   is still open…". The signal is still open in the Inbox. History shows "Previewed on this phone ·
   nothing sent" and a "You previewed" timeline entry. The approval needs a fresh **Prepare** before
   it can be tapped. Prepare again and approve. The wallet opens. Decline there, or sign a swap of a
   negligible amount, and see the outcome recorded once.

7. **Fee change during review.** Set a mainnet fee whose account is for the signal's output mint
   ([swap-fee-config.md](../development/swap-fee-config.md)). Prepare the signal: the review shows
   the fee. While it is open, run `set-fee` with another rate. Send the app to the background and
   bring it back, which makes it fetch the configuration. Then approve. Expect "The service fee
   configured for this app changed after this was prepared. Prepare it again and review the new
   terms." The wallet does not open. Prepare again: the review shows the new rate. Run
   `set-fee --bps 0` afterwards.

8. **Gateway unreachable.** Stop the gateway, or block its host. Prepare a signal: it prepares with
   the cached configuration. Move the device clock forward by more than 24 hours (Settings → Date &
   time, automatic time off) and prepare again. Expect "This app's gateway couldn't be reached for
   its network and fee settings, and none it gave earlier are recent enough to use. Nothing was
   prepared…". Restore the clock and the gateway, and the next preparation works.

9. **Restricted feed access is separate.** With the restricted feed demo
   ([restricted-feed-demo.md](../guides/restricted-feed-demo.md)), add the feed with access wallet A.
   The detail sheet shows **Access wallet** A. In a signal's review, choose wallet B for its network.
   The feed stays readable, its stream stays live, and the detail sheet still shows A.

10. **Direct connections unchanged.** Pair the test agent's direct server
    ([pairing.md](../guides/pairing.md)) and send a devnet transfer request. The review uses the
    connection's own wallet and network, shows no service fee and no preview action, and the sent
    transaction is confirmed through the gateway's devnet endpoint. Remove that endpoint
    (`set-rpc --network devnet`), bring the app to the foreground, and send another devnet transfer:
    its History entry waits on a missing endpoint (`no_rpc_endpoint`) instead of reading devnet
    through another network's endpoint. Set the endpoint again, bring the app to the foreground, and
    the record settles.
