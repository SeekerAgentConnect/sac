# SEE-108 — common request contract verification

Date: 2026-09-18

Baseline: `45132e8` (`origin/master`, including Stage 7.1 and `60e6ce3`)

pnpm 12.3.4, the local Android SDK, and Go 1.27.1 unpacked under `/tmp`. The implementation keeps
the existing proposal and private-request persistence formats readable while making
`seekervault.request.v2.Request` the shared source-authored envelope.

## Invariant coverage

- Gateway and publisher request validators accept source-authored presentation, capability,
  declarative owner inputs, audience and result mode only. Captured-traffic and schema tests reject
  subscriber wallet, chosen values, decisions, signatures and results.
- Feed execution still uses the device-local proposal record. Dismissal remains final across
  revisions, one execution is recorded before wallet access, and the binding pins the reviewed
  revision, selected wallet, plugin contract, owner choice and prepared bytes.
- A feed result has no upload path. Direct results continue through the existing sidecar retry
  path, scoped by connection and request identity.
- Sandbox execution remains simulation-only and production remains manual approval. No dynamic
  code, server-provided UI or unreadable-transaction fallback was added.
- Proposal store version 3 reads versions 1 and 2 and preserves proposal identity, revision,
  dismissal/execution, choices and preparation. Existing connection, result and activity stores
  were not replaced.
