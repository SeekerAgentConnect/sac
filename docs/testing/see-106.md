## Host and topology

Validation ran from the SEE-106 worktree on an Apple silicon macOS host. Docker CLI 20.10.22 and
Docker Compose v2.15.1 were present. The Docker daemon socket was a symlink into another macOS
user's home and rejected this user with `permission denied`, so no Compose container was claimed as
started. Go 1.27.1 for Darwin/arm64 and Centrifugo v6.9.6 were downloaded under `/tmp` to run the
repository's real-process checks; Caddy v2.10.2 was used to validate the deployed Caddyfile.

The deployment model checked was:

- public host ports 80/443 -> Caddy -> gateway read socket or Centrifugo's one unidirectional gRPC
  method;
- Docker-only `publisher-ingress` -> Caddy port 8082 -> gateway publisher socket;
- isolated `broadcast-inside` -> Centrifugo and non-persistent Redis;
- host loopback 8092/8094 -> the two authenticated demo APIs;
- optional direct sidecar on host loopback 8443, outside the gateway, preserving
  `seeker-agent-wallet-server_sidecar-data`.

## Addendum — first container run, and the Tailscale Funnel layout (2026-09-18)

Run on an Apple silicon Mac with a working Docker daemon (engine 20.10.22, Compose v2.15.1), from
`deploy/server`, under a throwaway project name with a self-signed certificate for
`gateway.test.ts.net` and Caddy's ports on host loopback. This was the first time the stack's
containers started, and three defects surfaced that configuration resolution could not show:

| Defect | Fix |
| --- | --- |
| `broadcast` restarted with `cannot open its database: unable to open database file (14)`: the scratch images declared `VOLUME /data` but had no `/data`, so Docker created the named volume as root's and uid 10001 could not write. `publisher/Dockerfile` had the same shape. | Both images now carry an empty `/data` owned by `10001:10001`; a new volume inherits it. |
| Every Caddy container restarted with `exec /usr/bin/caddy: operation not permitted`: the official binary carries the file capability `cap_net_bind_service`, and `cap_drop: ALL` put it outside the bounding set. `docker run --cap-drop ALL caddy:2.10-alpine caddy version` reproduces it; adding `--cap-add NET_BIND_SERVICE` runs. | `cap_add: NET_BIND_SERVICE` on `gateway-proxy`, `copytrading-proxy` and `prediction-proxy`. `broadcast/compose.yaml` and the publisher's own Compose file have the same block and were **not** changed or run here. |
| The guide's `grpcurl -proto /protos/…` fails: `must specify at least one import path if any absolute file paths are given`. | `-import-path /protos -proto centrifugal/…`. |

With those fixed, `-f compose.yaml -f compose.tailscale.yaml` (plus `compose.demos.yaml` for the
publisher):

- PASS: all four Part 1 services running; Redis, Centrifugo healthy; Caddy log free of errors.
- PASS: `openssl s_client -alpn h2` negotiated `h2` with the mounted certificate; an unknown SNI
  name failed the handshake.
- PASS: `GetServerManifest` for an unknown ID over HTTP/2 answered the structured `no_such_server`;
  `/healthz` on the TLS listener and the loopback port-80 binding answered nothing.
- PASS: `gateway-ctl register`, the CopyTrading demo's `publishing as this server` /
  `the manifest is published`, with `gateway=https%3A%2F%2Fgateway.test.ts.net` in its reference.
- PASS, streaming: `GetStreamTicket`, then `grpcurl` on `CentrifugoUniStream/Consume` through
  Caddy's TLS listener printed `connect` and a positioned subscription, and a `copytrading-ctl
  create` (state `published`) arrived as one `pub` on `feed:server/<ID>` at offset 3.
- PASS: a root process with no capabilities could not read a `0600` key owned by `10001:10001` and
  could read `0640` `10001:0`; uid 10001 read the latter too. This is the ownership
  `tls-from-tailscale.sh` now writes when `.env`'s `BROADCAST_DOMAIN` is the certificate's name.
- PASS: `tls-from-tailscale.sh` in a container as root with stand-in `tailscale` and `docker`
  commands: gateway-only `.env` (domain fallback, `0640 10001:0`, both restarts), sidecar with a
  gateway on another name (`0600 10001:10001`, sidecar restart only), and an unchanged second run.
- PASS: `compose.yaml` alone still publishes `80` and `443` when the two bind variables are unset.
- NOT RUN: Prediction demo; bind-mount directory permissions (Docker Desktop does not enforce host
  ownership on bind mounts — the guide's `chown 10001:10001` on each secrets directory follows from
  POSIX, not from a run here); anything on a real server: `tailscale cert`, Funnel `--tcp=443`,
  the public name, a phone.
- PASS (image-only layout): both Dockerfiles built for `linux/amd64` on Apple silicon with the
  compiler pinned to `$BUILDPLATFORM`; `/broadcastctl list` and `/publishctl` ran from the amd64
  images. An `rsync -aL` copy of `deploy/server` outside the repository, with `BROADCAST_IMAGE` set
  to the pushed tag and `up -d --no-build`, started all four services and answered the HTTP/2
  unary check. The demos were not started from the bundle.
