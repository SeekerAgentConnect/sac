# SEE-173 verification record

Date: 2026-09-29

SEE-173 names Jupiter's integrations as its agreement requires, adds prediction disclosures, and
lets a build add a SAC service fee to swaps, off by default. This records what was verified, how,
and what was not.

## Provider API, as tested

| What | Result (2026-09-29) |
| --- | --- |
| `GET https://lite-api.jup.ag/swap/v1/quote` (keyless), SOL→USDC and USDC→SOL, `onlyDirectRoutes`, `asLegacyTransaction`, with and without `platformFeeBps=20`/`25` | `200`. Without: `platformFee: null`. With: `platformFee {amount, feeBps}`, `amount = floor(gross × bps / 10 000)` of the route's output, `outAmount` net of it, `otherAmountThreshold` the slippage off the net amount. `instructionVersion: null`. |
| `POST https://lite-api.jup.ag/swap/v1/swap` with `feeAccount`, shared and own-accounts variants | `200`, a legacy transaction, no lookup tables. `shared_accounts_route` (`c1209b3341d69c81`) with the fee account at index 9, `route` (`e517cb977ae3ad2a`) at index 6; trailing `u8` = the fee bps; `quoted_out_amount` = the quote's net `outAmount`. No extra instruction is added for the fee. |
| `feeAccount` validation by the API | None: a wallet address was accepted as `feeAccount` and the build came back with `simulationError` (`0x1789`). The phone therefore verifies the account on chain itself. |
| Metis status | Jupiter marks the Metis Swap API (v1) as no longer actively maintained, superseded by Swap V2. v1 still answers keyless; nothing was migrated. |

Supported layouts with a fee: exactly those the inspector already read — the two v1 routing
instructions above, classic SPL Token accounts only, legacy messages, one hop, SOL/wrapped SOL via
the existing wrap/unwrap reading. Fee accounts must be classic SPL Token accounts in the swap's
output mint. Token-2022, V2 routing instructions and input-mint fees are not supported.

## Not verified here

- **No fee was collected on chain.** Fixtures, unit tests and unsigned builds prove what the phone
  would sign, not that a fee was credited. The owner's opt-in mainnet procedure is in
  [development/swap-fee-config.md](../development/swap-fee-config.md#manual-mainnet-verification-opt-in-spends-real-funds).
- **No emulator or device run.** This host has no KVM; the screens were verified with Robolectric.
- The release workflow's `android-apk` job has not been dispatched (it needs the owner's repository
  variables and the `SEEKERVAULT_SOLANA_RPC` secret).
