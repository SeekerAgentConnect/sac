# 2026-10-05

## Changed

- **The Home request tile is rebuilt (SEE-183).** Each tile in "Waiting for you" is a fixed
  214×200dp card in three rows: the kind icon and label with a status badge (a green check within
  rules, an orange `!` for warnings with the count from two up, nothing when nothing was checked);
  the question — or the amount and unit — as the title, always whole, at 22, 17 or 15sp by length;
  and the server chip with the arrival time. The "Signal" label, the outcome number, the caption,
  the question caption, the "In rules / N warnings" pill and the header server chip are gone; the
  server is named once. The same tile is on the debug component gallery. Design system:
  `RequestTileModel(title, sourceName, time, warningCount, sourceColour, unchecked)` replaces
  `supportingText`, `signatureByteCount`, `assetSymbol` and `footerText`; adds
  `RequestTileTitleSize`, `RequestTileStatus`, `statusLabel()`, `SourceChipSize.Small`, the
  `statusOk`/`onStatusOk` colours and the `tileTitle`/`badgeCount` type roles (pending the next
  design export, see `design/token-mismatches.md`). See
  [`docs/wiki/request-tile.md`](../wiki/request-tile.md).

- **Independent public releases: `@seekeragentconnect` on npm, GHCR images, signed APKs
  (SEE-182).** Each of the eight components — `server-sdk`, `mcp-server`, `mcp-skr-staking`,
  `gateway`, `gateway-centrifugo`, `demo-signals`, `demo-prediction`, `android` — is released on
  its own by its own `<component>-v<version>` tag, starting from a new public baseline of `0.0.1`.
  The pre-public `0.2.0-rc.*` numbers and the Docker Hub images stay recorded as history in
  `release/components.json` and are never rewritten.
  - npm packages moved to the **`@seekeragentconnect`** scope everywhere (names, imports, workspace
    filters, lockfile, Dockerfiles, tests, docs) with `SeekerAgentConnect/sac` metadata. The
    repository-wide forced npm dry run is gone: real releases publish with **trusted publishing
    (OIDC) and provenance**, using the npm CLI pinned in the manifest; a one-time bootstrap token is
    documented for each package's first version only.
  - Images publish to **`ghcr.io/seekeragentconnect/<component>`** — one repository each, amd64 and
    arm64, SBOM and provenance, OCI source/revision/version labels — with the workflow's
    `GITHUB_TOKEN`. The release workflow no longer needs or uses Docker Hub credentials, and every
    release proves its tags pull **anonymously** to the recorded digest.
  - The **Android app** is a release component: `versionName` and an explicit, increasing
    `versionCode` (`0.0.1` = `2`) come from the manifest, which Gradle now reads. A release builds
    the official configuration (Firebase client file, RPC, relay and discovery URLs, swap fee) from
    repository variables — refusing a service account or credential-bearing URL — signs with the
    permanent key from the `release` environment, checks the certificate against a pinned SHA-256,
    and publishes `sac-<version>.apk` with `SHA256SUMS` through a draft GitHub Release. Only stable
    app releases become the repository's latest release.
  - MCP versions no longer have to match or exceed the SDK's. Each MCP artifact records the SDK it
    vendors (`seekerAgentConnect.serverSdk` and `dist/vendor/server-sdk/package.json`: version and a
    SHA-256 of the vendored files), and the package tests verify it.
  - **Safe retries.** Before publishing, `scripts/release-state.mjs` reads npm, GHCR and GitHub
    Releases: an artifact already published from the same commit is verified and skipped, one from
    another commit stops the run, absence is only ever an explicit not-found, and `latest` moves
    only forwards. Publication is serialised per component and registry and never cancelled.
  - `pnpm release:bump <component> <version>` moves a version everywhere it is written.
  - **CI runs on pull requests and pushes again**, read-only and secret-free, and now also builds all
    six images for both platforms and checks the unsigned release APK's id and version.
  - `SeekerAgentConnect/do-deploy` and its deployments are unchanged; its Docker Hub references keep
    working. See `docs/development/releases.md` for the owner setup and the first `0.0.1` releases.

## Fixed

- **Wallet shows the full bottom navigation (SEE-183 review).** The Wallet tab had dropped the
  Discover item, so its bar had four items while every other tab had five. `ScreenScaffold` and
  `ScreenNavigationBar` no longer take an `includeDiscover` flag: every tab draws the same five
  items in the same order, with Wallet selected on Wallet.
- **Stale Android baselines re-recorded.** Eleven design-system and app screenshots no longer
  matched `master` (e.g. "the side and the stake" → "the amount" from SEE-181) and the
  `notification/kind-info` preview had no baseline or preview-naming entry; `verifyRoborazziDebug`
  failed on both modules without them.
