# 2026-10-11

## Added

- **Client configuration from the trusted gateway (SEE-185).** The APK carries one gateway origin
  (`-Pseekervault.gatewayUrl`, release `SEEKERVAULT_GATEWAY_URL`, `BuildConfig.GATEWAY_URL`). The
  gateway's operator sets the Solana RPC endpoint for mainnet, devnet and testnet and the SAC swap
  service fee once for every app that trusts it. The app fetches both from the new
  `FeedService.GetClientConfig`, caches them, and applies a change at once without a rebuild. The
  gateway stores the configuration in a single-row `client_config` table (SQLite schema 9, Postgres
  schema 5 with RLS). The revision moves by one with every real change, and saving an identical
  configuration changes nothing. It is set on the admin page (**Client configuration**) or with
  `feed-gatewayctl client-config show | set-rpc | set-fee`. Both validate it whole: https endpoints
  (loopback http only), no user info or fragment, fee 0–100 bps never clamped, base58 owner, mints
  and accounts. Everything in it is public, so a provider that needs a secret key goes behind the
  operator's own proxy. [docs/wiki/client-config.md](../wiki/client-config.md).
- **Every signal names its network (SEE-185).** `request.v2` contract version 2 adds the required
  `ActionCapability.network`. The gateway accepts only contract 2 for new publications. A missing or
  unknown network is `GATEWAY_PROBLEM_BAD_NETWORK`. A network the publisher's held manifest does not
  declare, or a publisher with no manifest yet, is the new `GATEWAY_PROBLEM_OTHER_NETWORK`
  (`failed_precondition`), checked in the publication's own transaction. Documents that declare a
  network are left out of the protocol-1 `ListProposals`/`GetProposal` views. On the phone a
  contract-1 document, or one with an unknown network, stays readable and is never executed.
  Nothing infers a network for it.
- **A feed operation's wallet is chosen per operation (SEE-185).** The review shows the signal's
  **Network** and the **Wallet** that will sign. The choice is remembered per feed and network. When
  there is no remembered choice, the only authorized profile on that network is used, and otherwise
  none. The phone never substitutes a profile from another network. A restricted feed's
  **Access wallet** is a separate identity, used only to prove access, and public feeds are added
  with no wallet. [docs/guides/wallet-setup.md](../guides/wallet-setup.md#feed-operations).
- **Preview without sending (SEE-185).** Beside a feed signal's approval, when the provider serves a
  preview, the owner can run the same preparation, inspection, rules and binding gate without
  opening the wallet. The preview is recorded beside the signal, and the signal stays open.
  Executing needs a fresh preparation. [docs/wiki/environments.md](../wiki/environments.md).

## Changed

- **SAC swap fee (SEE-173) comes from the gateway.** Feed swaps carry the gateway's terms for the
  signal's network, which are zero unless the operator sets a fee. Direct operations always carry
  none. The terms are pinned with the preparation and checked again before the wallet opens and
  inside the wallet lock. If they changed, the review says "The service fee configured for this app
  changed…" and the owner prepares again. Jupiter's on-chain account verification and the fee
  disclosure are unchanged. A failed fetch is never read as a zero fee. With no usable
  configuration (unreachable gateway and nothing cached within 24 hours, or an invalid answer), the
  operation is not prepared.
- **Solana RPC endpoints come only from the gateway (SEE-185, replacing SEE-184's sources).** There
  is no build default, owner setting or general fallback. Per-network genesis proof, wrong-cluster
  refusal, side-by-side networks and the debug-only local validator are kept. Confirmation, history
  and position reads use the cached endpoints of any age.
- **One trusted gateway (SEE-185).** Feed links, Discover cards and manifests that name another
  gateway are refused. A feed already stored from another gateway is readable and not executable.
  The relay and Discover use the same gateway.
- **Publishers (SEE-185).** The business API requires `network` on create and update (`bad_network`
  400, `other_network` 400, `network_fixed` 409), and `publishctl create|update` needs `--network`.
  Store schema 6 adds the signal's network. A signal stored before SEE-185 gets no network: it is
  refused locally (`no_network`) instead of being published open, and it can still be withdrawn.
  The `PublishProposal` fallback is removed. The CopyTrading trader form offers the manifest's
  networks, with mainnet selected. Prediction names mainnet on every signal and re-publishes older
  signals as a new generation. `PREDICTION_STATE=any` is allowed and logs a warning.
- **Direct manifests (server SDK, MCP server)** no longer emit environments. The manifest's
  fingerprint changes once, so its settings revision moves once on upgrade.

## Removed

- Server-declared environments: `ServerManifest.environments` (field 6), `ServerEnvironment`,
  `RecommendedFeed.environments` (9), `GATEWAY_PROBLEM_BAD_ENVIRONMENT` (12) and
  `GATEWAY_PROBLEM_OTHER_ENVIRONMENT` (34) are reserved. The gateway no longer validates manifest
  environments or holds them fixed, and it drops them from stored manifests. The phone's
  connection environment and its sandbox/production switch are gone, and Inbox rows always read
  Production.
- `PUBLISHER_ENVIRONMENT` and the `publisher-support/environment` package. A deployment that still
  sets the variable starts and logs that it is ignored.
- The Wallet → **Solana RPC** sheet, `RpcSettingsStore`, `RpcEndpointCard` and the
  `rpc-endpoint-card` design spec.
- The Android build settings `seekervault.solanaRpc*`, `seekervault.relayUrl`,
  `seekervault.discoveryUrl` and `seekervault.swapFee.*`, and the release variables
  `SEEKERVAULT_SOLANA_RPC*`, `SEEKERVAULT_RELAY_URL`, `SEEKERVAULT_DISCOVERY_URL` and
  `SEEKERVAULT_SWAP_FEE_*`. The release script reports one that is still set as retired and
  ignored. `releaseRequires` is now `["firebase", "gatewayUrl"]`.
- `pnpm check:swap-fee-build` and `scripts/check-swap-fee-build.sh`.

## Fixed

- **Overlapping client-configuration saves no longer lose a half (SEE-185 review).** The admin
  page's endpoint and fee forms and `feed-gatewayctl client-config set-rpc|set-fee` used to read the
  whole configuration, change one half and save the whole as a separate step, so a fee saved between
  the read and the write of an endpoint change (or the other way round) was silently written back.
  They now go through the new `PublisherAdminStore.UpdateClientConfig`, which applies the change to
  what is held and validates and writes the result in one write transaction (SQLite's single writer,
  Postgres's advisory write lock).
- **Signal API docs:** the minimal Python strategy loop in
  [signal-api.md](../integrations/signal-api.md#a-minimal-strategy-loop) now sends the signal's
  required `network`, which it omitted (a `400 bad_network`).

## Migration and deployment

These changes are breaking. In order:

1. **Upgrade the gateway first.** Its migrations add `client_config` and drop environments from
   stored manifests. No new environment variable is needed.
2. **Set the client configuration**, for example:
   `feed-gatewayctl client-config set-rpc --network mainnet --url <https endpoint>` for each network
   the app should read, and `set-fee` if the SAC fee was configured in the build before. Until then,
   the gateway answers revision 0: no endpoints and no fee. Chain reads and Prediction orders then
   fail and say why. [docs/development/swap-fee-config.md](../development/swap-fee-config.md).
3. **Upgrade publishers.** Send `network` on every create and update (`publishctl --network`). Delete
   `PUBLISHER_ENVIRONMENT`. If you ran a sandbox deployment and a production deployment of the same
   template, keep one: preview or execute is now the owner's choice on the phone. Signals from before
   SEE-185 have no network. Withdraw them and publish them again with one (the Prediction template
   does this itself).
4. **Build the app** with `SEEKERVAULT_GATEWAY_URL` (an origin), and remove the retired variables from
   the repository's Actions variables.
5. Feeds a phone added from a gateway other than the build's stay readable and can't be executed.
   Remove them and add them again from the trusted gateway.
