# 2026-09-18

## Added

- **A server deployment with the live update stream.** [`deploy/server/`](../../deploy/server/README.md) runs the sidecar alone on its own TLS listener — the one layout in which `UpdateService.Subscribe`, gRPC over HTTP/2 end to end, reaches the sidecar — with nothing in front of it that speaks HTTP. It is written for a Linux server on a tailnet: the certificate comes from `tailscale cert`, Tailscale Funnel passes TCP through in `--tcp` mode, and the sidecar binds the server's own loopback (`network_mode: host`, since the sidecar only ever binds loopback). `compose.yaml`, `.env.template`, and `tls-from-tailscale.sh` (issue or renew the certificate, and restart the sidecar when it changed; meant for cron) are the pieces, and the README is the numbered guide: certificate, Funnel, start, outside checks, pairing, **push (FCM) on the server** with a mounted service-account key and the fixed `GOOGLE_APPLICATION_CREDENTIALS` path, an agent entry with the port, operations, and troubleshooting. The trade is written down: with no gateway there is no route filter, so the Stage 1 diagnostic and `/healthz` are on the public origin behind their own tokens.
- **The sidecar image cross-builds.** [`sidecar/Dockerfile`](../../sidecar/Dockerfile) pins its install and compile stages to `$BUILDPLATFORM`, as the Render image already did, so `docker buildx build --platform linux/amd64` works from an Apple silicon Mac; the image itself is unchanged. Published as `docker.io/brenat/seeker-agent-connect:sidecar-v1`.

## Notes

- Nothing in the sidecar changed. The TLS listener, the update stream, and the FCM sender were all already there (`docs/development/sidecar.md`, `docs/guides/firebase.md`); this is the first shipped deployment that turns the listener on.
- The Compose gateway and the Render image keep their place for a deployment that wants route filtering more than the stream; behind them the phone keeps refresh, background sync, and push.

## Verification

- `deploy/server/README.md` carries the record: the image built natively and for `linux/amd64`, `docker compose config` with FCM on and off, and a container with a self-signed certificate advertising production updates at the public origin, negotiating `h2`, answering health, MCP, and pairing correctly, passing the healthcheck, and exiting cleanly on `SIGTERM`. **NOT RUN:** anything on a real server — `tailscale cert`, Funnel's TCP mode, a Seeker holding a stream through it, and a real push delivery.
