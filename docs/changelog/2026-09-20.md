# 2026-09-20

## Changed

- **Sheet motion.** Graph-owned bottom sheets wrap their content instead of stretching to the host.
  Max height is 150 dp from the top of the screen; taller content scrolls inside the sheet. Enter
  still slides the sheet by its own height in 260 ms, exit in 240 ms. A downward swipe (including
  a pull from the top of a scrolling body) closes the sheet the same way Back does. The contract
  is [`design/motion.md`](../../design/motion.md).

## Added

- **Prediction-demo serves a password-gated admin UI at `/trader` (SEE-138).**
  `prediction-admin` is a second App Platform service of the same image. Operators
  list signals already published to subscribers, search the provider listing with
  typed filters, and select a market for discovery to publish. Search returns at
  most ten markets and the page shows a loading state while a search or publish
  is in flight. `POST /v1/requests` stays 403. `ADMIN_PASSWORDS` holds the bcrypt
  file body. Login `admin` / `seeker-admin`. Rebuild as `prediction-0.1.2`.

- **HTTP/2 `/mcp` Host check reads `:authority`.** App Platform's h2c path omits the
  HTTP/1 `Host` header; the DNS-rebinding check now accepts `:authority`, and the
  hostname of `SIDECAR_PUBLIC_URL` is allowed without repeating it in
  `MCP_ALLOWED_HOSTS`.

- **MCP Live updates behind App Platform HTTP/2.** `SIDECAR_H2C=true` puts cleartext HTTP/2
  on the main listener and advertises `SIDECAR_PUBLIC_URL` as the update origin, for a
  TLS-terminating HTTP/2 proxy (`protocol: HTTP2` in `deploy/seeker-mcp.yaml`). App Platform
  HTTP health checks stay HTTP/1.1, so that spec uses a TCP check. Rebuild the image after
  this change. See [`docs/development/mcp-server.md`](../development/mcp-server.md#production-update-listener).

- **Signals-demo serves the CopyTrading trader UI at `/trader`.** `copytrading-admin` is a
  second App Platform service of the same image. `ADMIN_PASSWORDS` holds the bcrypt file
  body so App Platform does not need a bind-mounted secrets directory.

- **App Platform is four apps.** [`deploy/seeker-mcp.yaml`](../../deploy/seeker-mcp.yaml)
  is MCP only; [`deploy/seeker-gateway.yaml`](../../deploy/seeker-gateway.yaml) is the
  public-feed gateway (internal 8090/8091), a Caddy `edge` that splits FeedService and
  PublisherService, Redis, and Centrifugo; [`deploy/signals-demo.yaml`](../../deploy/signals-demo.yaml)
  and [`deploy/prediction-demo.yaml`](../../deploy/prediction-demo.yaml) are the CopyTrading
  and Prediction publishers and send to the gateway origin. The published gateway image
  (`gateway-0.1.2`) includes `/bin/sh` so App Platform Console can run `feed-gatewayctl`.

- **App Platform feed ingress matches the Connect FeedService path.** A prefix of
  `/seekervault.gateway.v1` does not match `/seekervault.gateway.v1.FeedService/…`
  (the next character is `.`, not `/`), so the phone's `GetServerManifest` never
  reached the gateway. The rule is now `/seekervault.gateway.v1.FeedService` with
  the path preserved.

- **The feed-gateway image has an App Platform console target.** Scratch has no
  `/bin/sh`, so App Platform's Console tab cannot exec into that component and
  `feed-gatewayctl register` cannot run against the live database. `--target console`
  copies static busybox to `/bin/sh`; Compose still builds the default scratch
  runtime. See [`feed-gateway/Dockerfile`](../../feed-gateway/Dockerfile).

- **App Platform spec now includes the public-feed stack and both demo publishers.**
  [`deploy/seeker-mcp.yaml`](../../deploy/seeker-mcp.yaml) keeps the existing MCP service at
  `/` and adds `brenat-seeker-gateway` (unary FeedService on this origin, publisher API
  internal-only), `brenat-seeker-copytrading`, `brenat-seeker-polymarket` (Prediction with
  Polymarket filters), internal Redis, and Centrifugo on HTTP/2 for
  `/centrifugal.centrifugo.unistream.CentrifugoUniStream/Consume`. The broker image is
  [`feed-gateway/Dockerfile.centrifugo`](../../feed-gateway/Dockerfile.centrifugo), which
  copies the pinned `centrifugo.yaml` because App Platform cannot bind-mount it.

- **`vault_create_pairing_link` issues the pairing deep link over MCP.** Hermes (or any agent
  with `MCP_TOKEN`) can call it and get `pairing_uri` (`seekervault://pair?…`) plus `https_url`
  (`https://<origin>/pair?…`). `GET /pair` is an unauthenticated landing page that 302s to the
  deep link. The phone also accepts the HTTPS URI when pasted under Add connection. The owner
  still confirms on the phone; the tool does not complete pairing. See
  [`docs/guides/pairing.md`](../guides/pairing.md).

- **SEE-132 packages the self-hosted MCP server for npm and Docker.** The former `sidecar/` product

## Changed

- **SEE-136 reconciles and verifies the final two-mode architecture.** Active operator and
  developer documentation now agrees on the Direct Server SDK, standalone MCP application, shared
  public-feed gateway, non-deployable publisher support library, independent demos and canonical
  deployment projects. The final gate adds a literal pre-environment public-feed upgrade fixture,
  fixes the Android HTTP/2 proof server's stale `sidecar/` working directory, and extends deployment
  guards to reject retired roots and obsolete active-doc/code paths. Exact SDK and MCP tarballs,
  native gateway/demo/direct flows, restarts/outboxes, notifications, upgrades, generated sources,
  Android and the final build pass. Docker, live broker/Redis/TLS, current Hermes/OpenClaw, live
  Firebase/Jupiter and physical-device checks remain explicitly **NOT RUN**, so parent SEE-128
  stays In Progress. See [`docs/testing/see-136.md`](../testing/see-136.md).

- **SEE-135 separates portable applications from ingress and host-specific networking.**
  `deploy/feed`, `deploy/mcp`, `deploy/copytrading`, and `deploy/prediction` are now the only base
  Compose entry points, and each starts only its own application/dependencies. Public feed and
  direct Caddy projects have separate lifecycles under `deploy/ingress`; Tailscale/Funnel and
  certificate mounts are isolated under `deploy/operators`. No active preset uses service-namespace
  or host networking. Feed ingress carries the exact HTTP/2 Centrifugo stream, while the direct
  reverse-proxy example deliberately excludes production updates and documents native TLS plus raw
  TCP/VPN forwarding instead.

  SQLite stays local with explicit physical volume names and configurable file paths. The operator
  guide maps every standalone, old direct, and old combined volume lineage—including
  CopyTrading's different database filename—without automatic merging or destructive cleanup.
  Centrifugo's Redis URL, credentials, TLS verification settings, and prefix are configurable.
  Trusted proxy CIDRs keep per-reader limiting correct after removing shared network namespaces.
  A daemon-free gate resolves eight presets and checks services, ports, routes, Redis relocation,
  and durable identities. Docker runtime, real TLS streaming, external Redis connection, and
  physical-device checks are explicitly **NOT RUN** on this host; see
  [`deploy/README.md`](../../deploy/README.md) and
  [`docs/testing/see-135.md`](../testing/see-135.md).

- **SEE-134 extracts two independent root-level demo servers.** The single `publisher/` module is
  gone. `publisher-support/` is the source library the demos share — the durable
  publication/outbox engine, the gateway HTTP/Connect client, the feed document rules, the business
  API frame and the operator CLI's implementation — and it is deliberately not a service and not a
  published feed-publisher client: no command, no image, no listener, no deployment.
  `demo-copytrading/` and `demo-prediction/` are independently buildable, imageable and runnable
  modules, each with its own Dockerfile, Compose stack, Caddy front door, `.env.example`, database,
  publisher identity, gateway credential and step-by-step guide. Neither imports, builds or starts
  the other, and neither needs the Direct SDK or the MCP server; each demo's own `internal/boundary`
  package asserts it over that module's source. Both publish only through the gateway's documented
  authenticated HTTP/Connect JSON API.

  The market and discovery rows stayed in `publisher-support/store`, because a market row and its
  signal are written in one transaction by the same durable engine and splitting them would have
  meant duplicating that engine or giving up the atomicity; the filters, the reconciler and the
  Jupiter client are `demo-prediction`'s, so no provider code reaches the CopyTrading image.
  Generated contracts moved to `publisher-support/gen` from the renamed
  `buf.gen.publisher-support.yaml`. `pnpm check:publisher` became `pnpm check:publisher-support`,
  `pnpm check:copytrading` and `pnpm check:prediction`, and CI's one publisher job became three,
  each demo's job also building that demo's image.

  Compose projects, volumes and database paths are unchanged — `seeker-publisher`/`publisher-data`,
  `seeker-prediction`/`prediction-data`, and `deploy/server`'s `copytrading-data`/`prediction-data`
  — so an existing installation reuses its data; `deploy/server` reads `COPYTRADING_IMAGE` with
  `PUBLISHER_IMAGE` as its fallback and adds `PREDICTION_IMAGE`. No publisher identity, credential,
  revision or environment stamp is regenerated because a directory changed. See
  [`demo-copytrading/README.md`](../../demo-copytrading/README.md),
  [`demo-prediction/README.md`](../../demo-prediction/README.md),
  [`docs/development/demos.md`](../development/demos.md) and
  [`docs/testing/see-134.md`](../testing/see-134.md).

- **SEE-133 isolates the shared public-feed gateway.** The canonical Go module now lives at
  `feed-gateway/` with renamed server/operator commands, generation/check/CI paths, and updated
  in-place demo, integration, load, and deployment callers. Business and RPC code depend on focused
  storage contracts while `internal/storage/sqlite` alone owns SQL, schema, and transactions. The
  existing database, volume, configuration, protocol identities, ports, and uid remain compatible;
  publication plus outbox remains atomic, with explicit commit-failure and duplicate-delivery
  coverage. Its independent Dockerfile/README documents plain Connect JSON publication, separate
  public/internal origins, operator lifecycle, and local-SQLite backup/rollback. No private gateway
  route, demo extraction, remote database, or portable deployment redesign was added. See
  [`feed-gateway/README.md`](../../feed-gateway/README.md) and
  [`docs/testing/see-133.md`](../testing/see-133.md).

- **The MCP product hosts the SDK through its public API.** MCP/OAuth, process and listener
  configuration, Solana/Firebase implementations, operator CLI and Docker/npm packaging live in
  `mcp-server/`. Production host code has no private SDK import and no duplicate direct request
  engine.

- **SEE-130 retires gateway-private routing end to end.** Direct pairing/results and public feed
  publication/subscription are now the only active paths. The gateway invitation/device/private
  publisher RPCs, third listener, proxy routes, publisher SDK helpers/examples and generated
  bindings are removed, with their wire identifiers reserved and deny-listed. Broadcast schema v3
  drops private routing state while preserving public feed data and publisher grants. Android
  storage v5 rewrites old private connections to an inert explanation, removes their credentials
  and unfinished delivery work, and requires a fresh direct pairing without converting an origin
  or token. CLI text/QR, typed input and Android `seekervault://pair` links now share the same
  owner-confirmed direct onboarding flow.

## Fixed

- **SEE-137 hardens direct ownership and completes generic deployment.** The MCP process now holds
  a dedicated SQLite/VFS ownership transaction instead of trusting a PID file, so `SIGKILL`, PID
  reuse, Docker PID 1, and container replacement release ownership without manual deletion while
  a live competing writer is still refused. The persistent owner database is local-filesystem only,
  and a compatibility guard prevents an older binary from silently overlapping after upgrade.

  The container health program now follows cleartext or native TLS configuration, connects through
  loopback, verifies the advertised hostname and trust chain, and supports an explicit extra CA
  without a trust-all mode. Native TLS exposes production MCP, pairing/request, and HTTP/2
  UpdateService routes while keeping remote health and the legacy live diagnostic absent.

  A generic `deploy/mcp/compose.tls.yaml` overlay replaces the Tailscale-specific duplicate.
  Collision-free combined overlays give feed reads host port 8090 and join demos to a distinct
  private publisher network. [`deploy/README.md`](../../deploy/README.md) is now the one numbered
  clean-host guide for direct-only, feeds-only, and combined deployment, with real client/SAC,
  restart, backup, and rollback checks. Docker-backed execution remains explicitly **NOT RUN** on
  the verification host where the daemon socket is denied; no workflow was weakened and no package
  or image was published.

- **CopyTrading trader login from Chrome on the Funnel origin (SEE-126).** Chrome sends
  `Origin: null` on a same-origin form POST when the page used `Referrer-Policy: no-referrer`,
  so `/trader/login` answered 403 “that request did not come from this page” while curl with a
  real Origin succeeded. The UI now uses `same-origin`, treats a literal `null` Origin as absent,
  and accepts `Sec-Fetch-Site: same-origin` (the header in that Chrome request). Cross-site
  `Origin` values are still refused.
