# 2026-10-01

## Fixed

- **Public-feed publishers catch up with the revision the gateway holds (SEE-179).** The Prediction
  and Signals demos showed "No network declared" although both declare Mainnet. During one rolling
  deployment, the demos started with a fresh database and published revision 1 to a gateway older
  than SEE-174. That gateway dropped `feed.supported_networks` and answered `unchanged`. Afterwards,
  any restart was refused for ever with `revision_conflict`, because `publisher-support` ignored the
  `held_revision` the gateway names. It now uses it. On `stale_revision` it republishes at the held
  revision, and on `revision_conflict` at the next one, at most twice. Every start sends the
  manifest again. A demo whose database did not survive a redeployment (App Platform has no volume)
  therefore moves its manifest forward instead of stopping, and phones pick up the new revision
  without reconnecting. See `docs/testing/see-179.md`.

## Documentation

- Both demo READMEs have a **Checking the declared network** section: the public `curl` that shows
  what phones read, the expected `SOLANA_NETWORK_MAINNET`, and the restart that recovers a missing
  declaration. The Signals README states why that demo is Mainnet and cannot be Devnet: it uses
  `jupiter.swap`, and `sandbox` is not a cluster. The `.env.example` files say to upgrade the
  gateway before the demos. `docs/wiki/server-manifests.md` covers deployment order and the
  catch-up.

## Migration and deployment

- Rebuild and redeploy both demo images after the gateway's rollout has finished. The gateway is
  already `gateway-0.2.3` in the DigitalOcean deployment. No environment change is needed:
  `PUBLISHER_SUPPORTED_NETWORKS` unset declares `mainnet` for both demos, and `devnet` is refused.
