# 2026-10-01

## Changed

- **The Prediction demo publishes one entry per event, chosen to cover every configured category and
  keyword (SEE-177).** A cycle now reads its whole candidate pool, groups markets by venue + the
  provider's event ID (a normalized title only when there is no ID), and spends
  `PREDICTION_MOST_OPEN` on *events*: first those already held and still eligible, then greedily the
  events covering the most configured buckets nothing covers yet (rebalancing a redundant held event
  when that widens coverage), then further distinct events by variety. Each event is published as
  one representative market — the held one, else the soonest-closing — whose ID and outcome title the
  proposal carries. Second open proposals for one event, including those published one-per-market
  before this change, are withdrawn (`duplicate_event`); a held event the walk no longer finds
  eligible gives its slot to an eligible one; an expired proposal no longer counts against the
  ceiling; nothing is rebalanced or replaced on a failed walk; an operator's own selection is pinned
  and replaces its event's entry. Keywords and categories are normalized (NFKC, case, spacing) and
  counted once. Every cycle records its selection — candidate, event and selected counts, covered
  buckets and uncovered ones with `no_eligible_candidate` / `walk_incomplete` / `capacity_limit` —
  in `GET /v1/discovery`, the log and a new **Feed coverage** table on the admin page. Store schema 5
  adds `market.pinned` and `discovery.selection`. See
  [`docs/wiki/prediction-template.md`](../wiki/prediction-template.md#selection-one-entry-per-event-chosen-for-coverage-see-177)
  and the live run in [`docs/testing/see-177.md`](../testing/see-177.md).

## Removed

- **The Prediction admin page's per-row Retry (SEE-177).** Each published row still shows its state,
  publication status and any problem; the publisher's own backoff keeps retrying a publication the
  gateway could not take, and `ctl retry <id>` remains for a refusal since fixed. The CopyTrading
  admin and the app's retry flows are unchanged.

## Fixed

- **Public-feed publishers catch up with the revision the gateway holds (SEE-179).** The Prediction
  and Signals demos showed "No network declared" although both declare Mainnet. During one rolling
  deployment, the demos started with a fresh database and published revision 1 to a gateway older
  than SEE-174. That gateway dropped `feed.supported_networks` and answered `unchanged`. Afterwards,
  any restart was refused for ever with `revision_conflict`, because `publisher-support` ignored the
  `held_revision` the gateway names. It now uses it. On `stale_revision` it republishes at the held
  revision, and on `revision_conflict` at the next one, at most twice. Every start sends the
  manifest again. A demo whose database did not survive a redeployment (App Platform has no volume)
  therefore moves its manifest forward instead of stopping, and phones pick up the new revision
  without reconnecting. See `docs/testing/see-179.md`.
- `TestGatewayAcceptsWhatThePredictionTemplatePublishes` looked for provider links in a shape the
  document does not use (terms are `{"key","text"}` pairs) and failed on `master` whenever the real
  gateway was built.

## Documentation

- Both demo READMEs have a **Checking the declared network** section: the public `curl` that shows
  what phones read, the expected `SOLANA_NETWORK_MAINNET`, and the restart that recovers a missing
  declaration. The Signals README states why that demo is Mainnet and cannot be Devnet: it uses
  `jupiter.swap`, and `sandbox` is not a cluster. The `.env.example` files say to upgrade the
  gateway before the demos. `docs/wiki/server-manifests.md` covers deployment order and the
  catch-up.

## Migration and deployment

- Rebuild and redeploy both demo images after the gateway's rollout has finished. The gateway is
  already `gateway-0.2.3` in the DigitalOcean deployment. No environment change is needed:
  `PUBLISHER_SUPPORTED_NETWORKS` unset declares `mainnet` for both demos, and `devnet` is refused.
