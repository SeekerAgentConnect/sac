# 2026-10-12

## Changed

- **Every component bumped to `0.0.2`.** `pnpm release:bump <component> 0.0.2` for all eight
  components in `release/components.json`: `server-sdk`, `mcp-server`, `mcp-skr-staking`,
  `gateway`, `gateway-centrifugo`, `demo-signals`, `demo-prediction` and `android`. The npm
  manifests and the MCP servers' version constants move with it, and the Android `versionCode` goes
  from 2 to 3 (`previousVersionCode` 2). The release carries what landed since `0.0.1`
  ([2026-10-10](2026-10-10.md), [2026-10-11](2026-10-11.md)). Nothing is published until the
  `<component>-v0.0.2` tags are pushed on the merge commit
  ([docs/development/releases.md](../development/releases.md#releasing-one-component)).

## Fixed

- **The `android-v0.0.2` release failed its checks.** The `android` component's release checks
  were only `pnpm check:android`, but 25 of its unit tests (`RealSidecar`, `GrpcBidiInteropTest`,
  the Stage 2/5.2/5.3 acceptance tests) start the real MCP server, which imports
  `packages/server-sdk/dist` — and no install creates it. CI's Android job builds the SDK first;
  the release did not. `release/components.json` now runs `pnpm build:server-sdk` before
  `pnpm check:android`, and `scripts/release-plan.test.mjs` pins that order. The failed run stopped
  before the gate, so nothing was published: the `android-v0.0.2` tag can be moved to the fixed
  commit and pushed again.
