# 2026-09-27

## Changed

- **Every deployment file moved to [`do-deploy`](https://github.com/SeekerAgentConnect/do-deploy).**
  The rest of `deploy/` — the self-hosted Compose presets (feed, MCP, SKR staking, CopyTrading,
  Prediction and their combined/TLS overlays), the Caddy HTTPS ingress projects, the Tailscale/Funnel
  example and the clean-host runbook — is now under `compose/` there, beside the App Platform specs.
  The presets run only published `docker.io/brenat/seeker-agent-connect` images (each still
  overridable through its `*_IMAGE` variable, now including `CENTRIFUGO_IMAGE`), so `up -d --build`
  becomes `up -d` and Centrifugo uses the published broker image instead of mounting
  `services/gateway/centrifugo.yaml`. `do-deploy` checks them with `scripts/check-compose.mjs`;
  `pnpm check:deployments` here keeps only the repository-side checks and fails if `deploy/`
  reappears. The unused `deploy/server/` compatibility links and a demo-signals test that always
  skipped on a missing Tailscale Caddyfile are gone. Volumes, project names and ports are unchanged,
  so a running deployment keeps its data; run its commands from a `do-deploy` checkout.
- **The DigitalOcean App Platform specs moved to their own repository.** `deploy/seeker-gateway.yaml`,
  `deploy/seeker-mcp.yaml`, `deploy/seeker-skr-staking-mcp.yaml`, `deploy/signals-demo.yaml` and
  `deploy/prediction-demo.yaml` are now under `apps/` in
  [`do-deploy`](https://github.com/SeekerAgentConnect/do-deploy), together with the app IDs and the
  `doctl` commands that were in `deploy/README.md` § 9. That repository deploys only the published
  `docker.io/brenat/seeker-agent-connect` images and needs no checkout of this one. `deploy/` keeps
  the self-hosted Compose presets; the running apps are unchanged.
- **Images publish to Docker Hub again, one repository with a tag prefix per component.** The
  release workflow pushes every image to `docker.io/brenat/seeker-agent-connect` instead of
  `ghcr.io/seekeragentconnect`, keeping the tag prefixes used before SEE-168: `mcp-`,
  `skr-staking-mcp-`, `gateway-`, `centrifugo-`, `copytrading-` and `prediction-`, each followed by
  the version, `latest` (stable only), `sha-<commit>` or `develop`. The prefix is `image.tagPrefix`
  in [`release/components.json`](../../release/components.json), and `pnpm check:release` refuses
  two components sharing one. The job logs in with the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN`
  secrets; `GHCR_TOKEN` is no longer used.
- **npm releases are a dry run.** `registries.npmDryRun: true` in the manifest makes every npm
  release — tag or dispatch — run `npm publish --dry-run`: the package is built and packed, nothing
  is uploaded, and an already-published version is a warning rather than a failure. Set the flag
  to `false` to publish again. [docs/development/releases.md](../development/releases.md) and
  [docs/guides/installation.md](../guides/installation.md) describe both.
- **Repository prepared for public release.** The README is rewritten as a short public overview:
  what the app does, the component table, getting started and the main development commands; the
  per-ticket milestone log it carried stays in this changelog. Internal per-ticket artifacts are
  removed: `docs/reviews/` (visual review captures), `docs/evidence/` (emulator screenshots),
  `docs/development/see-128-migration-map.md`, the two `emulator-e2e-see*.md` run logs, and the
  `.claude/plans/` session notes that were tracked despite being git-ignored. Links to them are
  removed; older changelog entries keep their historical references.
- **Examples are plain examples.** `examples/` no longer carries ticket references, links into the
  private deployment repository, or sample server UUIDs. The two demo READMEs now run the image with
  plain `docker run` and the operator client with `go run ./cmd/publishctl` instead of the external
  Compose presets, and write server IDs as `<server-uuid>`. The Compose-only `PUBLISHER_PORT`/
  `PUBLISHER_BIND` and `PREDICTION_PORT`/`PREDICTION_BIND` entries are gone from the `.env.example`
  files, and the Dockerfiles keep only the `org.opencontainers.image.source` link the release check
  requires.
