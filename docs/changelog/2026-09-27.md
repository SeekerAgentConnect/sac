# 2026-09-27

## Changed

- **The DigitalOcean App Platform specs moved to their own repository.** `deploy/seeker-gateway.yaml`,
  `deploy/seeker-mcp.yaml`, `deploy/seeker-skr-staking-mcp.yaml`, `deploy/signals-demo.yaml` and
  `deploy/prediction-demo.yaml` are now under `apps/` in
  [`do-deploy`](https://github.com/SeekerAgentConnect/do-deploy), together with the app IDs and the
  `doctl` commands that were in `deploy/README.md` § 9. That repository deploys only the published
  `docker.io/brenat/seeker-agent-connect` images and needs no checkout of this one. `deploy/` keeps
  the self-hosted Compose presets; the running apps are unchanged.
- **Images publish to Docker Hub again, one repository with a tag prefix per component.** The
  release workflow pushes every image to `docker.io/brenat/seeker-agent-connect` instead of
  `ghcr.io/seekeragentconnect`, keeping the tag prefixes used before SEE-168: `mcp-`,
  `skr-staking-mcp-`, `gateway-`, `centrifugo-`, `copytrading-` and `prediction-`, each followed by
  the version, `latest` (stable only), `sha-<commit>` or `develop`. The prefix is `image.tagPrefix`
  in [`release/components.json`](../../release/components.json), and `pnpm check:release` refuses
  two components sharing one. The job logs in with the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN`
  secrets; `GHCR_TOKEN` is no longer used.
- **npm releases are a dry run.** `registries.npmDryRun: true` in the manifest makes every npm
  release — tag or dispatch — run `npm publish --dry-run`: the package is built and packed, nothing
  is uploaded, and an already-published version is a warning rather than a failure. Set the flag
  to `false` to publish again. [docs/development/releases.md](../development/releases.md) and
  [docs/guides/installation.md](../guides/installation.md) describe both.
