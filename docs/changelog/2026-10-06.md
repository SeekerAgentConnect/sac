# 2026-10-06

## Fixed

- **Release publishers can no longer be skipped by an unused build branch (SEE-182).** Every
  component skips at least one of `npm-pack`, `image-build` and `android-build`, and GitHub's
  implicit `success()` would then have skipped `npm-publish`, `image-publish` and
  `android-publish` even after `gate` passed. `gate`, each publisher and `github-release` now state
  their status condition explicitly, and `github-release` is written only after every publisher the
  component selects has succeeded, so it can no longer record an empty integrity or digest. The new
  `scripts/release-workflow.test.mjs` evaluates the workflow's job graph for every component.
- **A version bump no longer breaks `pnpm check:release` (SEE-182).** The planner and bump tests
  stopped assuming the live manifest stays at `0.0.1`: fixed-version scenarios use a pinned copy,
  the live manifest is held to version-independent invariants, and a regression bumps one
  component in a scratch repository and runs the release checks on it. `check-release.mjs` accepts
  a repository path for this.
- **Retrying an older Android release after a newer one shipped verifies it (SEE-182).** The
  increasing-`versionCode` guard now applies only to creating or resuming a release; an
  already-published tag is checked against its own record (commit, version, code, APK name and
  SHA-256), keeps its APK and does not move `latest`.
