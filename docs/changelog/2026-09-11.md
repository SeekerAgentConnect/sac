## Added

- **Repository bootstrap (SEE-6 / SAW-001):**
  - a pnpm workspace with the TypeScript/Node sidecar skeleton, which validates the Stage 1 configuration
  - an empty Kotlin/Compose/Material 3 Android app, application ID `io.github.brrenat.seekervault`
  - Buf configuration with pinned code generators
  - the root command contract: `check`, `check:android`, `generate`, `dev:sidecar`, `agent`, `test:hello`
  - `.env.example`
  - GitHub Actions CI covering formatting, lint, type checks, and tests, plus Android unit tests, lint, and a debug APK build
- **New docs:** `README.md`, `AGENTS.md`, `docs/development/toolchain.md`
- **Live-command protocol (SEE-8 / SAW-002):**
  - `LiveCommandService` with a foreground-only `WatchCommands` server stream and a unary `AcknowledgeCommand`
  - `LiveCommand`, `CommandAcknowledgement`, and the `LiveCommandError` reasons
  - TypeScript and Kotlin code generated with Buf
  - protocol rules in the sidecar: text limits, the deadline boundary, and one in-flight command
  - cross-runtime binary fixtures written by `buf convert`
  - `pnpm check:generated`
  - new doc: `docs/protocol.md`
- **Live MCP command bridge (SEE-9 / SAW-003):**
  - The sidecar serves `/mcp` (MCP Streamable HTTP) with `vault_display_command`, the phone's Connect `LiveCommandService`, and `/healthz`, on loopback.
  - An in-memory bridge holds one watcher and one waiting call. It returns OFFLINE, BUSY, and TIMEOUT, and returns CANCELLED when the agent cancels, the agent's connection drops, the phone disconnects, or the sidecar shuts down.
  - MCP and phone requests use separate bearer tokens, checked in constant time. `/mcp` rejects non-loopback Host and Origin headers, and no token or command text reaches the logs.
  - Integration tests use the real MCP SDK and Connect clients, and a restart test runs the sidecar as a real process.
  - New doc: `docs/development/sidecar.md`.
