- **Durable request contract (SEE-16 / SAW-009):**
  - `seekervault.request.v1` contains:
    - `PairingService`, with `Pair` and `RevokeConnection`
    - `RequestService`, with `ListPending`, `GetRequest`, `PrepareRequest`, and `SubmitResult`
    - `ActionRequest`, scoped by connection and request ID
    - the ack, sign_message, transfer, and swap actions
    - `RequestState`, `PreparedTransaction` with a version and content hash, `PolicyEvaluation`, and `RequestError`
  - The lifecycle:
    - ten states and every allowed transition, with who causes each one
    - success is COMPLETED for ack and messages, and CONFIRMED for transactions
    - a request expiry that is separate from the transaction's blockhash expiry
  - Idempotency keys, with the parameters fingerprinted, so a retry that changes them is refused rather than silently reused
  - The agent's MCP tools for the durable workflow, specified for SAW-010 and the later stages
  - The rules as tested pure code in `sidecar/src/requests/`, and cross-runtime fixtures checked by the sidecar and by `RequestProtocolFixturesTest`

- **Persistent sidecar queue (SEE-17 / SAW-010):**
  - Storage:
    - The sidecar stores durable requests in a local SQLite database through Node's built-in `node:sqlite`, at `DATABASE_PATH` (by default `sidecar/data/sidecar.db`).
    - The database runs in WAL mode with full synchronous commits, and numbered migrations run at startup. A database from a newer sidecar is refused.
    - Every operation commits in one transaction before it answers, so the agent and the phone never hear of a change that isn't on disk. Nothing runs on its own after a restart.
  - The agent's MCP tools `vault_request_ack`, `vault_get_request`, and `vault_cancel_request` answer at once. A retried idempotency key returns the original request, and a changed retry gets `IDEMPOTENCY_CONFLICT`.
  - The phone's `RequestService`, whose errors carry a `RequestErrorDetail`:
    - `ListPending`: keyset pages that never repeat or skip a request
    - `GetRequest`
    - `SubmitResult`: a repeated result changes nothing, and a conflicting one gets `INVALID_STATE`
    - `PrepareRequest`: an ack has nothing to prepare
  - Limits:
    - Expiry is applied first in every operation.
    - `REQUEST_PENDING_LIMIT` caps how many requests wait for the owner (`PENDING_LIMIT`).
    - `REQUEST_TTL_SECONDS` sets the default lifetime.
    - `/mcp` bodies are limited to 64 KiB.
  - Until pairing (SAW-011), the sidecar has one connection, created with its database, and `PHONE_TOKEN` authenticates as it.
  - Tests cover:
    - the store and the database, with its frozen v1 fixture
    - MCP and Connect end to end
    - cancellation races, and pagination while states change
    - restarts after SIGKILL
- **Secure pairing and separate roles (SEE-18 / SAW-011):**
  - Pairing:
    - `pnpm pair` issues a one-use pairing token, and shows it as a QR code and as a `seekervault://pair?…` URI, together with the server URL and the sidecar's lasting ID. The token expires after 10 minutes (`PAIRING_TOKEN_TTL_SECONDS`), works once, and a newer code voids it.
    - `PairingService.Pair` exchanges the token for a new connection and its credential. The token is bound to the URL in its code, and pairing never changes an existing connection.
    - One phone is paired at a time. Pairing again, `RevokeConnection`, or `pnpm pair revoke` revokes the previous connection at once and cancels its PENDING requests. `pnpm pair status` shows the paired phone.
    - The sidecar keeps only SHA-256 hashes of pairing tokens and credentials, and logs neither.
  - Roles: `MCP_TOKEN` opens `/mcp` only, the pairing token opens `Pair` only, and the phone credential opens `RequestService` and `RevokeConnection`. `PHONE_TOKEN` stays with the Stage 1 `LiveCommandService`.
  - `SIDECAR_PUBLIC_URL` sets the URL that pairing codes carry. It must be HTTPS, apart from the loopback development URL. A phone on another network reaches the loopback sidecar through a trusted TLS endpoint, such as Tailscale Serve or Caddy.
  - Tests cover:
    - every credential against every RPC and MCP method
    - expired, reused, unknown, and wrong-URL pairing tokens
    - revocation and re-pairing, and a new code never changing an existing connection
    - pairing through a TLS endpoint, with certificate and host name failures
    - no secret in the log or in the CLI's output
  - New doc: `docs/security.md`. `docs/protocol.md` gets the pairing format and the role matrix.
- **Android pairing and connections (SEE-19 / SAW-012):**
  - Screens:
    - The app opens on **Connections**, the sidecars the phone is paired with.
    - **Add connection** scans the `pnpm pair` QR code with CameraX and ZXing, or takes the code typed in. It shows the server for the owner to confirm before pairing.
    - **Connection details** refreshes, renames, and disconnects. Disconnecting revokes the connection on its sidecar first.
  - The camera permission is asked for only when the owner taps **Scan QR code**. If it's refused, or there's no camera, the owner types the code instead. A malformed code gets the reason.
  - Storage:
    - Each connection is keyed by its connection ID: its metadata in one JSON file, and its credential encrypted with AES-256-GCM under a non-exportable Android Keystore key, with the connection ID as associated data.
    - Credentials sit in `noBackupFilesDir`, and nothing is backed up or transferred.
  - Isolation:
    - A credential goes only to its own connection's URL.
    - A code never changes an existing connection.
    - A credential the sidecar rejects is deleted.
    - Requests from another connection are ignored.
  - The Stage 1 live test is one tap away, and leaving it closes its stream.
  - Tests cover:
    - two connections, rename, restart, and revocation
    - untrusted and mismatched certificates
    - camera denial, and malformed pairing data
    - removing one connection without touching another
    - secrets kept out of the log, the disk, and the screens
    - the real sidecar, and the real Keystore key on a device or emulator
  - New doc: `docs/guides/pairing.md`. `docs/security.md` gets local storage and recovery.
- **Pending inbox and queued acknowledgements (SEE-20 / SAW-013):**
  - The phone fetches every page of pending requests over unary RPCs when the app opens, when a connection is opened, or on **Refresh**. It doesn't need the Stage 1 stream, push, or a background service.
  - **Pending requests** lists what's waiting for the owner, answers waiting to be sent, and answers already settled. Each request shows its source, action, age, and expiry, and there are empty, offline, and error states.
  - **Request details** acknowledges or rejects a queued acknowledgement.
    - Both buttons are disabled while the answer is sent.
    - A reopened request shows the stored outcome instead of the buttons.
    - The agent's note is shown apart, marked as not verified.
  - Delivery:
    - The answer is stored before it's sent, and a failure or a lost response keeps it.
    - It's sent again on the next refresh or on **Send again**, and the sidecar recognizes the repeat.
    - A request the agent cancelled first is marked superseded, from the `RequestErrorDetail`.
    - Answers are keyed by connection and request ID, so identical request IDs on two servers stay apart.
  - `pnpm agent ack`, `get`, and `cancel` drive the durable tools from the command line, with exit code 9 when the sidecar refuses.
  - Tests cover:
    - a request made while the app was closed, fetched, answered, and read back (real sidecar)
    - lost responses, retries, restarts, and duplicate taps
    - overlapping sends, refresh, and identical request IDs on two servers
    - no submissions on load, and no push library
  - New docs: `docs/guides/pending-requests.md`, `docs/testing/stage-2.md`.

## Changed

- **`RFC.md`:** Stage 1 is now a wallet-free hello world, and the stage table follows the implementation backlog.
- **The app explains a failed first connection.** Instead of "Connection lost", it names the URL and asks whether the sidecar is running and `adb reverse` was run for that port.
- **pnpm enforces Node 24.21 through `devEngines.runtime`,** which replaces `engines`. pnpm 12 ignored `engines` and ran on Node 24.20.0 without a warning.
- **Integration docs live in `docs/integrations/`.** `CLAUDE.md` now points there, and the empty `docs/guide/` placeholder is gone.
- **The test agent reports a dropped connection at once,** as exit code 3, instead of waiting for its client timeout and reporting `TIMEOUT`.
- **`pnpm check:android` also builds the instrumentation test APK.**
- **Node is pinned exactly:** `devEngines.runtime` requires 24.21.0, the same version as `.nvmrc`.
- **`MCP_ALLOWED_HOSTS`, optional, lets `/mcp` accept a VPN address.** It replaces the Tailscale address that `e035411` wrote into the code. The Hermes guide documents the Tailscale setup.
- **Stage 1 is accepted.** The owner's Hermes → Seeker → OK → Hermes round trip passed on 2026-09-11.
- **Stage 2 has started.** `README.md` and `AGENTS.md` name it as the current stage. `RFC.md`'s contract table now lists `RevokeConnection` and `RequestState`, and its MCP tools include `vault_cancel_request` and the development-only `vault_request_ack`.
- **The sidecar now has a database.** The Node stage guard allows storage only in `sidecar/src/storage/`. Test harnesses give every sidecar they start a throwaway database. `.env.example` lists `DATABASE_PATH`, `REQUEST_TTL_SECONDS`, and `REQUEST_PENDING_LIMIT`.
- **`/mcp` lists the durable tools after `vault_display_command`, and refuses a body over 64 KiB with 413.**
- **`RequestService` takes the paired phone's credential instead of `PHONE_TOKEN`.** SAW-010's stand-in connection is gone. Migration 2 revokes it and cancels its PENDING requests, and until a phone pairs, creating a request fails with `NOT_PAIRED`.
- **`PairRequest` gains `server_url`, and `PairResponse` gains `server_id`.** Both are new fields, and `buf breaking` passes.
- **The sidecar's startup line names the server ID and the paired phone,** instead of the stand-in connection.
- **QR pairing is no longer out of scope** in `AGENTS.md`, which now requires every new RPC or tool to join the role matrix test.
- **The app asks for `CAMERA`, and the camera is optional.** `StageOneBoundaryTest` is now `StageBoundaryTest`. It allows storage and Keystore keys only in `connections/storage/`, and checks that nothing is backed up.
- **`LiveCommandDeviceTest` taps Live test first,** since the app now opens on Connections.
- **The connection repository also holds the inbox.** Refreshing a connection now sends its waiting answers first, then fetches every page. `ListPending` takes page tokens in the app, and `GatewayException` carries the request from an `INVALID_STATE` detail. `StageBoundaryTest` also rules out push libraries.
- **`vault_request_ack` is a demo tool, served only with `MCP_DEMO_TOOLS=true`.**
  - `.env.example` sets it. An existing `.env` needs the new line before `pnpm agent ack` works.
  - A sidecar without it serves `vault_display_command`, `vault_get_request`, and `vault_cancel_request`, and its instructions and startup log say so.
  - `pnpm agent ack` exits 3 and names the variable when the sidecar doesn't offer the tool.

## Fixed

- **Found in the review of PR #2:**
  - When a command's deadline passed just before the next command arrived, the first MCP call could wait forever. The overdue command now times out first.
  - A request target that isn't a path, such as `//[`, now gets 400 instead of stopping the sidecar.
  - The sidecar now refuses to start with a token that can't travel in a bearer header, such as one containing a space.
  - The app now rejects a server URL whose port is outside 1 to 65535, instead of failing on **Connect**.
  - `pnpm test:hello --device` now recognizes the Seeker by its brand and model. Other phones no longer count as the Seeker check.
- **The emulator job no longer restores the Gradle cache.** Once the Android job had saved an 886 MB cache, restoring it left 6.1 GB of disk free. The emulator needs 7.2 GB for its data partition, so it never booted (CI runs 34593182239 and 34596730552). The `disk-size: 4096M` tried in between didn't lower that need, and it's removed.
