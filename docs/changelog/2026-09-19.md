# 2026-09-19

## Added

- **Password-gated CopyTrading trader UI for hackathon judges (SEE-126).**
  `publisher/cmd/copytrading-admin` is a client of the existing `/v1` API, shipped in the same
  publisher image. `compose.demos.yaml` runs it beside CopyTrading; the API stays on
  `127.0.0.1:8092` and the public origin serves only HTML at `/trader`. Named bcrypt passwords,
  path-scoped session cookies, in-memory rate limits, and an optional publisher create cap
  (default unlimited). See [`deploy/server/README.md`](../../deploy/server/README.md) and
  [`docs/testing/see-126.md`](../testing/see-126.md).

- **Android now has one state-driven review-sheet template for all five review variants
  (SEE-120).** `ReviewSheetState` is UI-only, and Transfer, Swap, Prediction, Signature, and
  Acknowledge are exact-copy fixtures rendered by the same natural-height, non-scrolling
  composable. Direct requests and signal reviews map through the SEE-108 common envelope in
  `:app`; warning states keep the primary action disabled until confirmation. Five full-height
  Roborazzi captures and labelled reference/actual evidence are included, while the existing
  approval, rejection, simulation, and wallet hand-off lifecycle remains unchanged.

- **The Android design system now includes the reusable organism tier (SEE-119).** Request tiles
  and their snapping carousel; merged Inbox and Activity rows; server and rule rows; verdict,
  owner-input, and terms cards; wallet summary and handoff surfaces; and a scroll-safe sheet
  scaffold are stateless Compose APIs assembled from the existing atom and molecule tiers. All 43
  generated variants record at 3× with committed side-by-side evidence. The sheet keeps its header
  and actions pinned while its body scrolls, and the 358dp carousel preserves SEE-81 endpoint
  snapping while highlighting the centred request.

- **The Android design system now includes the reusable molecule tier (SEE-118).** Fact and daily
  rows, segmented and Inbox tab selectors, navigation items, section headers, text fields, notice
  cards, empty states, and source-filter bars are stateless Compose APIs assembled only from theme
  values and SEE-117 atoms. Twenty-two exact-copy variants record at 3× with committed side-by-side
  evidence, including the long identifier cases and a four-item bottom-navigation assembly.

- **The Android design system now has its first reusable component tier (SEE-117).** Chips,
  verdict and signal marks, source avatars, buttons, the FAB, and accessible switch/check/radio
  rows are stateless Compose APIs backed only by named theme tokens. Fifty-three exact-text
  previews record at 3× and have committed side-by-side design evidence. Source identity uses one
  deterministic shared colour allocator. The review also records two guide gaps rather than
  inventing styling: icon-button has no hand-written spec, and the dark tertiary-button colour has
  no token in `design/tokens.json`.

- **The Claude Design export is now an implementation-ready in-repo guide (SEE-111).** All 34
  ticket-listed components have a local contract beside their exact rendered HTML and scale-3 PNG
  references, including enum-backed Kotlin API proposals, dependency boundaries, builder notes, and
  open questions. `request-tile` remains one component with rail and centred states. The guide also
  maps the exported navigation flow and records the Kotlin token cross-check. Capture refresh safety
  and the guide-maintenance workflow remain owned by SEE-116.
- **One design-guide workflow now governs UI implementation and design changes (SEE-116).**
  [`design/README.md`](../../design/README.md) gives agents the fixed spec → HTML → PNG → tokens
  read order, the px-to-dp/sp and scale-3 contract, stateless Compose API rules, token boundaries,
  known Compose traps, and the Roborazzi + `designCompare` loop. The new
  [`design/UPDATING.md`](../../design/UPDATING.md) keeps every refresh design-only through one
  nine-step export, diff, documentation, changelog, follow-up, and sanity-check procedure. A
  hand-written [`spec.md` template](../../design/components/_template/spec.md) pins the component
  fields SEE-111 supplies. The guide also closes the generic-dimension escape hatch: production
  `:designsystem` components cannot consume pass-through `dpN` properties, and named Kotlin tokens
  are checked against generated `tokens.json`. `CLAUDE.md` now directs UI and guide work to those
  instructions.
- **Every design-system Compose preview now renders to PNG on the JVM (SEE-115).** Roborazzi and
  ComposablePreviewScanner discover the previews, Robolectric renders them with native graphics at
  `w390dp-h1500dp-xxhdpi` (a maximum window that accommodates SEE-120's unrolled sheets), and a
  required `@DesignRef` gives each capture the same component/variant path and slug as the design
  guide. Captures are dark-only, wrapped in `SeekerTheme`, and bounded by their composable with no
  comparison padding. `pnpm check:android` records all of them in the normal no-emulator CI job.
- **`./gradlew designCompare` makes scale and coverage visible.** After a record run it writes
  labelled `reference | actual` PNGs under `android/build/design-compare` and reports matches and
  missing files in both directions. It does not declare visual equality and the HTML reference is
  not a Roborazzi regression baseline.
- **Rendering probes pin the environment before component work expands.** A 48dp box records at
  exactly 144px, the theme swatch matches an existing 3× SEE-113 reference, the font probe checks
  explicit Roboto variable weights and Roboto Mono advance, and the icon probe renders `close`,
  `content_copy`, `toll`, `refresh`, and `delete` from Material Icons Outlined. `:app` has the same
  disabled scanner wiring for SEE-121; SEE-124 still owns approved baselines and CI verification.

## Fixed

- **Design capture crops to the specimen, defaults to scale 3, and installs on a clean checkout
  (SEE-125).** Follow-up to SEE-113. Playwright's element screenshot still expands to whole CSS
  pixels; the capture tool now crops that buffer in device pixels from the fractional bounding box
  with `sharp`, asserts the uncropped size is the enclosing integer rect × `deviceScaleFactor`, and
  fails if a PNG is not `round(bbox × dsf)`. Default scale is 3 (Roborazzi's `xxhdpi`), `--dsf`
  remains, and `manifest.json` records 3. `design/tools` installs Chromium in `postinstall`, depends
  on `sharp`, and pins both in `package-lock.json`. First run is
  `cd design/tools && npm install`, then `npm run design:capture` from the repository root
  (`design/README.md`). Regenerated component and screen PNGs at scale 3:
  `button/variant-filled-size-lg.png` is 505×144; phone frames are 1170×2532. See
  [`docs/testing/see-125.md`](../testing/see-125.md) and
  [`docs/development/design-capture.md`](../development/design-capture.md).
