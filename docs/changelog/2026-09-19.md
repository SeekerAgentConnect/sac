# 2026-09-19

## Fixed

- **Design capture crops to the specimen, defaults to scale 3, and installs on a clean checkout (SEE-125).** Follow-up to SEE-113. Playwright's element screenshot still expands to whole CSS pixels; the capture tool now crops that buffer in device pixels from the fractional bounding box with `sharp`, asserts the uncropped size is the enclosing integer rect × `deviceScaleFactor`, and fails if a PNG is not `round(bbox × dsf)`. Default scale is 3 (Roborazzi's `xxhdpi`), `--dsf` remains, and `manifest.json` records 3. `design/tools` installs Chromium in `postinstall`, depends on `sharp`, and pins both in `package-lock.json`. First run is `cd design/tools && npm install`, then `npm run design:capture` from the repository root (`design/README.md`). Regenerated component and screen PNGs at scale 3: `button/variant-filled-size-lg.png` is 505×144; phone frames are 1170×2532. See [`docs/testing/see-125.md`](../testing/see-125.md) and [`docs/development/design-capture.md`](../development/design-capture.md).
