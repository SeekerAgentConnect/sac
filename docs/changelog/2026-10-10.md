# 2026-10-10

## Added

- **Solana RPC settings per network, on the phone (SEE-184).** Wallet → **Solana RPC** shows
  mainnet, devnet and testnet side by side: the host each is asked at and where that comes from
  (your setting, this build's endpoint, this build's general endpoint), what asking it found, and
  **Check and save** / **Use build default**. Saving asks the endpoint's genesis hash first and
  keeps it only when it names the network; a change applies at once, in the foreground and in
  background work, with no rebuild or restart, and persists across restarts. There is no app-wide
  network switch: a mainnet feed and a devnet server work at the same time.
  [docs/wiki/solana-rpc.md](../wiki/solana-rpc.md), manual check in
  [docs/testing/see-184.md](../testing/see-184.md).

## Changed

- **One resolver for every on-device chain read (SEE-184).** Prediction lookup tables, swap fee
  account verification, prediction sales, SKR staking positions and confirmation/history reads all
  go through `rpc/SolanaRpc`, each read naming the network its operation was bound to. Precedence:
  the owner's setting, then the build's endpoint for that network, then the legacy general
  `seekervault.solanaRpc` — the last only after its genesis hash proves the network. It is a
  selection, not a failover. Account reads no longer depend on the general endpoint: a build with
  only `seekervault.solanaRpc.mainnet` verifies Prediction orders and swap fee accounts.
- **Wrong-cluster endpoints are refused for account reads too** (`rpc_wrong_cluster`), not only
  for confirmations. Missing, unreachable or wrong-network endpoints block preparations that need
  account verification and leave confirmation checks retryable; nothing ever falls back to another
  network's endpoint. Repairing a network's endpoint makes that network's waiting checks due at
  once; other networks' records are untouched and no record changes network.
- **Build and release configuration.** A swap fee build is satisfied by
  `seekervault.solanaRpc.mainnet` alone (the general endpoint still works); the release gate's
  `solanaRpc` feature is satisfied by `SEEKERVAULT_SOLANA_RPC_MAINNET` alone, and general-only
  configurations still pass. Build values remain initial defaults and extractable client
  configuration; only hosts are ever shown outside the settings field, stored, or logged.
